# AutoCheck (site056) 의도적 오류 상세 보고서 (bug.md)

이 문서는 `site056` (AutoCheck 중고차 점검·예약 플랫폼)에 구현된 5개의 Intentional Error (SEC-456 ~ SEC-460)에 대한 상세 명세와 재현 절차를 기술합니다.

---

## 1. site056-SEC-456: 204 No Content 응답 JSON 파싱 오류

1. **Bug ID**: `site056-SEC-456`
2. **오류 유형**: `API Response Handling` (`empty-response-json-parse`)
3. **발생 조건**: '내 예약' 페이지에서 방문 예정 상태의 예약을 선택하고 취소 확정을 누를 때
4. **정상 동작**: 서버가 취소 처리 후 HTTP `204 No Content`를 반환하면 클라이언트는 응답 본문 파싱을 생략하고 성공 상태로 UI를 갱신해야 한다.
5. **실제 동작**: 프론트엔드 API 클라이언트(`src/api/client.js`)의 `request` 함수가 모든 `response.ok` 응답에 대해 무조건 `await response.json()`을 호출하여 본문이 비어 있는 204 응답 파싱 시 `SyntaxError: Unexpected end of JSON input` 예외가 발생한다.
6. **재현 절차**:
   - 상단 네비게이션에서 [내 예약] 클릭
   - [예정] 상태의 예약 항목 우측 [예약 취소] 버튼 클릭
   - 모달 팝업에서 [예약 취소 확정] 버튼 클릭
   - 브라우저 개발자 콘솔 및 화면 상단 에러 배너 확인
7. **관련 API**: `DELETE /api/bookings/:id`
8. **관련 파일**: `src/api/client.js`, `server.js`
9. **오류 원인**: 204 상태코드 검사 없이 `response.json()`을 무조건 호출하는 프론트엔드 API 래퍼 구현
10. **PPO가 관찰할 수 있는 현상**: 서버에서는 취소되었으나 프론트엔드 상단에 빨간색 에러 알림(`SyntaxError: Unexpected end of JSON input`)이 노출되고 사용자 흐름이 중단됨
11. **기대되는 탐색 trajectory**:
    ```text
    내 예약 → 예정 예약 선택 → 예약 상세/목록 → 예약 취소 → 취소 확인 → JSON 파싱 예외 관찰
    ```

## 2. site056-SEC-457: 최신 요청이 이전 AbortController에 의해 취소되는 오류

1. **Bug ID**: `site056-SEC-457`
2. **오류 유형**: `Async Request` (`stale-abort-controller`)
3. **발생 조건**: '차량 찾기' 페이지의 검색창에 사용자가 빠른 연속 타이핑으로 여러 글자를 입력할 때
4. **정상 동작**: 이전 요청이 진행 중일 때 새 글자가 입력되면 이전 요청만 abort되고 최신 요청은 정상 완료되어야 한다.
5. **실제 동작**: 새로 생성된 `AbortController`를 ref에 먼저 저장한 후 이전 요청을 abort하려다 방금 생성된 최신 컨트롤러를 abort(`controllerRef.current.abort()`)하여 최신 검색 요청이 `AbortError`로 즉시 취소된다.
6. **재현 절차**:
   - 상단 네비게이션에서 [차량 찾기] 클릭
   - 통합 검색창에 '현', '현대', '현대 그랜저'를 연속으로 빠르게 입력
   - 검색 결과 및 에러 메시지 상태 확인
7. **관련 API**: `GET /api/vehicles?search=`
8. **관련 파일**: `src/pages/Vehicles.jsx`
9. **오류 원인**: 이전 AbortController 레퍼런스를 보관하기 전에 새 인스턴스로 ref를 덮어써서 최신 요청을 실수로 abort시키는 비동기 핸들러 버그
10. **PPO가 관찰할 수 있는 현상**: 검색어를 입력했음에도 화면에 "검색 요청이 중단되었습니다." 경고가 나타나거나 최종 입력한 검색어에 맞는 결과 목록이 로드되지 않음
11. **기대되는 탐색 trajectory**:
    ```text
    차량 찾기 → 검색창 클릭 → 빠르게 여러 글자 입력 → 검색 취소 에러 및 결과 불일치 관찰
    ```

## 3. site056-SEC-458: 파일 확장자와 MIME Type 검증 불일치

1. **Bug ID**: `site056-SEC-458`
2. **오류 유형**: `File Upload` (`mime-extension-mismatch`)
3. **발생 조건**: 점검 리포트 페이지에서 서류/사진 첨부 업로드 시
4. **정상 동작**: 서버는 파일의 확장자뿐만 아니라 실제 `MIME Type`(`image/jpeg`, `application/pdf` 등)을 상호 대조하여 올바른 파일 형식인지 검증해야 한다.
5. **실제 동작**: 서버 업로드 핸들러가 파일명 끝의 확장자 정규식(`.jpg`, `.pdf` 등)만 확인하고 본문의 `mimeType`을 무시하여, 확장자만 속인 다른 타입의 파일이 정상 통과되거나 반대로 올바른 파일이 거절될 수 있다.
6. **재현 절차**:
   - 상단 네비게이션에서 [점검 리포트] 클릭
   - 하단 '첨부 서류 및 현장 점검 사진' 영역의 [파일 드롭존] 클릭
   - 파일명은 `test.jpg`이나 실제 MIME 타입은 `application/pdf`인 파일 전송
   - 서버에서 정상 201 Created로 수락되는 비정상 검증 동작 확인
7. **관련 API**: `POST /api/reports/:reportId/documents`
8. **관련 파일**: `server.js`, `src/components/FileDropzone.jsx`, `src/pages/Report.jsx`
9. **오류 원인**: 서버에서 `req.body.mimeType`에 대한 엄격한 화이트리스트 검사 없이 파일 이름의 확장자 문자열만 검사함
10. **PPO가 관찰할 수 있는 현상**: MIME type과 파일 확장자가 일치하지 않는 조작된 파일이 검증을 통과하여 리포트에 등록됨
11. **기대되는 탐색 trajectory**:
    ```text
    점검 리포트 → 관련 서류 → 파일 추가 → 파일 선택 → 업로드 → 확장자만 검증하는 취약점 관찰
    ```

## 4. site056-SEC-459: API 오류 상태코드를 200으로 반환하는 오류

1. **Bug ID**: `site056-SEC-459`
2. **오류 유형**: `API Contract` (`http-status-error-contract`)
3. **발생 조건**: 특정 마감된 충돌 슬롯(예: AutoCheck 강남센터 10:00 슬롯)으로 예약을 신청할 때
4. **정상 동작**: 예약 생성 실패 시 서버는 HTTP `400 Bad Request` 또는 `409 Conflict`와 같은 에러 상태코드를 반환해야 한다.
5. **실제 동작**: 서버가 실패 응답임에도 HTTP `200 OK` 상태코드와 함께 `{ success: false, message: "해당 시간은 이미 예약되었습니다." }`를 반환하여 프론트엔드가 성공(HTTP 200)으로 판단하고 예약 완료 단계로 진행하지만, 실제로는 DB에 예약 데이터가 저장되지 않는다.
6. **재현 절차**:
   - [점검 예약] 페이지 이동
   - 점검 센터: [AutoCheck 강남센터] 선택
   - 일자: 임의 일자, 시간대: [10:00] 선택
   - 예약자 성명/전화번호 입력 후 [예약 확정하기] 클릭
   - 화면에 "점검 예약이 완료되었습니다!" 완료 화면 표시 확인
   - 상단 [내 예약] 메뉴로 이동하여 방금 신청한 예약이 목록에 없는 상태 확인
7. **관련 API**: `POST /api/bookings`
8. **관련 파일**: `server.js`, `src/pages/Booking.jsx`
9. **오류 원인**: 비즈니스 로직 실패에 대해 HTTP 200을 반환하는 API Contract 규약 위반
10. **PPO가 관찰할 수 있는 현상**: UI에서는 성공 안내가 나오지만 실제 데이터가 생성되지 않아 '내 예약' 목록에서 누락되는 심각한 상태 불일치 관찰
11. **기대되는 탐색 trajectory**:
    ```text
    점검 예약 → 강남센터 선택 → 10:00 시간 선택 → 예약 확정 → 완료 화면 확인 → 내 예약 이동 → 예약 미생성 확인
    ```

## 5. site056-SEC-460: Unicode 정규화 차이로 인한 정확 검색 실패

1. **Bug ID**: `site056-SEC-460`
2. **오류 유형**: `Text Search` (`unicode-normalization-mismatch`)
3. **발생 조건**: 차량 찾기 페이지에서 모델명 필터에 NFD로 저장된 '제네시스 G80' 또는 '그랜저 GN7'을 검색할 때
4. **정상 동작**: 사용자가 브라우저에서 입력한 표준 한글(NFC)과 백엔드 데이터(NFD)가 동일 텍스트라면 Unicode 정규화를 통해 정상 매칭되어야 한다.
5. **실제 동작**: 백엔드가 문자열 검색 시 Unicode 정규화(`.normalize("NFC")`)를 수행하지 않아 바이트 레벨에서 문자열이 불일치하여 명백히 존재하는 매물이 검색 결과에서 누락된다.
6. **재현 절차**:
   - [차량 찾기] 페이지 이동
   - '모델명 필터' 입력란에 `제네시스 G80` 입력
   - [적용] 버튼 클릭
   - 매물이 존재함에도 불구하고 "총 0대의 점검 매물이 검색되었습니다" 및 빈 결과 화면 표시 확인
7. **관련 API**: `GET /api/vehicles?model=`
8. **관련 파일**: `server.js`
9. **오류 원인**: 백엔드에서 검색어 및 대상 필드에 대해 Unicode NFC 정규화 처리를 생략하고 단순 `.includes()` 비교 수행
10. **PPO가 관찰할 수 있는 현상**: 눈에 보이는 동일한 한글 문자열을 정확히 입력했음에도 검색 결과가 0건으로 나오는 현상 관찰
11. **기대되는 탐색 trajectory**:
    ```text
    차량 찾기 → 모델명 필터 입력('제네시스 G80') → 필터 적용 → 0건 결과 및 매물 누락 관찰
    ```
