### SEC-431: 상세 페이지 뒤로가기 후 이전 데이터 stale state 표시
* **SEC ID:** `SEC-431`
* **오류 이름:** 라우팅 파라미터 변경 시 상세 데이터 상태 불일치
* **오류 유형:** navigation / stale-route-state
* **발생 조건:** 여행기 A 상세 조회 -> 여행기 B 상세 조회 후 브라우저 뒤로가기 버튼을 클릭했을 때
* **정상 동작:** URL이 `/travel/101`로 변경되면 즉시 101번 여행기의 제목, 작성자, 일정 데이터가 렌더링되어야 함
* **현재 동작:** 컴포넌트 상태가 초기화되지 않아 URL은 101번이나 화면에는 102번 여행기 정보가 일시적으로 유지되거나 불일치 상태로 남음
* **관련 API:** `GET /api/travel-logs/:id`
* **관련 UI:** TravelDetail 페이지 제목 및 작성자 영역
* **관찰 가능한 결과:** URL 파라미터와 화면에 노출되는 여행기 제목의 ID/내용 불일치
* **PPO 탐색 흐름:** `여행기 101 진입` → `하단 추천 여행기 102 클릭` → `뒤로가기 클릭` → `URL과 화면의 여행기 제목 비교`

### SEC-432: 댓글 작성 후 요약 댓글 수 집계 불일치
* **SEC ID:** `SEC-432`
* **오류 이름:** 새 댓글 등록 시 commentCount 집계값 미동기화
* **오류 유형:** synchronization / aggregate-count-mismatch
* **발생 조건:** 여행기 상세 화면에서 새 댓글을 작성하여 [등록] 버튼을 누를 때
* **정상 동작:** 댓글 목록에 새 댓글이 추가됨과 동시에 상단 및 하단의 `댓글 N개` 카운트가 +1 증가해야 함
* **현재 동작:** 댓글 목록에는 새 댓글이 렌더링되지만 상단 요약 정보의 `commentCount`는 이전 값을 유지함
* **관련 API:** `POST /api/travel-logs/:id/comments`, `GET /api/travel-logs/:id`
* **관련 UI:** TravelDetail 상단 통계 뱃지, CommentList 헤더
* **관찰 가능한 결과:** 댓글 리스트에는 5개가 보이나 헤더에는 "댓글 4개"로 서로 다른 숫자가 표기됨
* **PPO 탐색 흐름:** `여행기 상세 진입` → `현재 댓글 수 확인` → `새 댓글 작성 및 등록` → `목록 개수와 상단 표시 숫자 비교`

### SEC-433: 무한 스크롤 시 동일 데이터 중복 렌더링
* **SEC ID:** `SEC-433`
* **오류 이름:** 무한 스크롤 페이지 요청 시 중복 항목 append
* **오류 유형:** list-rendering / infinite-scroll-duplicate
* **발생 조건:** 여행기 목록 화면에서 스크롤을 아래로 빠르게 내려 2페이지 이상의 데이터를 로드할 때
* **정상 동작:** 1페이지에 노출되지 않은 새로운 고유 ID의 여행기들만 목록 하단에 덧붙여져야 함
* **현재 동작:** 오프셋 계산 중복으로 인해 이전 페이지의 마지막 2개 항목이 다음 페이지에도 다시 포함되어 렌더링됨
* **관련 API:** `GET /api/travel-logs?page=2&limit=6`
* **관련 UI:** TravelList 페이지 무한 스크롤 리스트
* **관찰 가능한 결과:** 스크롤 시 같은 제목과 ID를 가진 여행기 카드가 목록에 연속으로 두 번 나타남
* **PPO 탐색 흐름:** `목록 페이지 진입` → `스크롤 하단 이동` → `추가된 카드 목록에서 중복된 여행기 ID/제목 탐색`

### SEC-434: 이미지 로딩 실패 시 이전 카드 이미지 재사용 (잘못된 Fallback)
* **SEC ID:** `SEC-434`
* **오류 이름:** 이미지 로딩 오류 시 잘못된 이전 이미지 fallback
* **오류 유형:** media / image-fallback
* **발생 조건:** 대표 이미지 URL이 유효하지 않은 특정 여행기(104번 강릉 등) 카드가 렌더링될 때
* **정상 동작:** 이미지 로드 실패(onError) 시 준비된 기본 플레이스홀더(Default Travel Image)가 노출되어야 함
* **현재 동작:** 직전에 성공적으로 로드된 다른 여행기 카드의 이미지 URL을 fallback으로 재사용하여 관련 없는 사진이 표시됨
* **관련 API:** `GET /api/travel-logs`
* **관련 UI:** TravelCard 대표 썸네일 이미지
* **관찰 가능한 결과:** 강릉 커피거리 여행기 카드에 부산 해운대 바다열차 사진이 대표 이미지로 렌더링됨
* **PPO 탐색 흐름:** `여행기 목록 탐색` → `104번 강릉 여행기 카드 확인` → `노출된 이미지와 여행지 제목 매칭 검증`

### SEC-435: PATCH 부분 수정 시 전달되지 않은 필드 덮어쓰기
* **SEC ID:** `SEC-435`
* **오류 이름:** PATCH 부분 업데이트 처리 중 기존 필드 손실
* **오류 유형:** update / partial-update-overwrite
* **발생 조건:** 여행기 수정 화면에서 제목만 수정하여 저장 요청(PATCH)을 보낼 때
* **정상 동작:** 요청 본문에 포함된 `title`만 수정되고, `destination`, `description`, `tags` 등은 기존 데이터가 보존되어야 함
* **현재 동작:** 백엔드에서 전달되지 않은 필드를 빈 문자열(`""`)로 덮어써서 기존 여행지와 설명이 초기화/유실됨
* **관련 API:** `PATCH /api/travel-logs/:id`
* **관련 UI:** TravelEditor [저장하기] 버튼 및 수정 완료 후 TravelDetail 화면
* **관찰 가능한 결과:** 제목 수정 후 상세 페이지를 확인하면 여행지와 소개글이 모두 빈 칸으로 사라져 있음
* **PPO 탐색 흐름:** `여행기 수정 페이지 진입` → `제목만 변경 후 저장` → `상세 페이지에서 여행지/소개글 유실 확인`
