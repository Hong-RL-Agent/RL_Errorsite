# RideOn (site057) 의도적 오류 상세 보고서 (bug.md)

이 문서는 `site057` (RideOn 공유 모빌리티 대여 플랫폼)에 구현된 5개의 Intentional Error (SEC-461 ~ SEC-465)에 대한 상세 명세와 재현 절차를 기술합니다.

---

## 1. site057-SEC-461: 숫자형 ID를 문자열 ID와 잘못 비교하는 오류

1. **Bug ID**: `site057-SEC-461`
2. **오류 유형**: `Data Comparison` (`type-sensitive-identifier-comparison`)
3. **발생 조건**: 사용자가 주변 차량 목록 또는 홈 화면에서 특정 차량을 선택하여 상세 페이지로 이동할 때
4. **정상 동작**: URL 파라미터로 전달된 ID(`"102"`)에 해당하는 차량 데이터(ID: `102`)를 정상적으로 조회하여 상세 정보를 표시해야 한다.
5. **실제 동작**: 백엔드 `server.js`의 `GET /api/vehicles/:id` 핸들러에서 `vehicles.find(v => v.id === req.params.id)`로 비교하여, Number 타입인 `v.id`와 String 타입인 `req.params.id` 간의 strict comparison이 항상 `false`가 되어 404 상태코드와 함께 "차량을 찾을 수 없습니다."가 반환된다.
6. **재현 절차**:
   - [주변 차량] 또는 [홈] 화면에서 'RideOn Bike 102' 카드의 [상세보기] 버튼 클릭
   - 차량 상세 페이지로 이동
   - 화면에 "차량을 찾을 수 없습니다." 에러 뷰가 노출되는 현상 확인
7. **관련 API**: `GET /api/vehicles/:id`
8. **관련 파일**: `server.js`, `src/pages/VehicleDetail.jsx`
9. **오류 원인**: JavaScript strict equality(`===`) 사용 시 타입 변환(`Number()`) 누락
10. **PPO가 관찰할 수 있는 현상**: 목록에는 엄연히 존재하는 차량임에도 상세 페이지에서 404 에러 화면이 출력됨
11. **기대되는 탐색 trajectory**:
    ```text
    홈/주변 차량 → 특정 차량 카드 [상세보기] 클릭 → 차량 상세 페이지 이동 → "차량을 찾을 수 없습니다" 화면 관찰
    ```

## 2. site057-SEC-462: NaN이 요금 계산 결과에 전파되는 오류

1. **Bug ID**: `site057-SEC-462`
2. **오류 유형**: `Numeric Calculation` (`NaN-propagation`)
3. **발생 조건**: 이용 기록에서 특정 이용 내역(`RO-20260928-309` / `rt-103`)을 클릭하여 상세 요금 영수증을 열람할 때
4. **정상 동작**: 요금 산정 시 기본 요금과 주행 시간 기반 계산이 정상적인 숫자로 산출되어야 한다.
5. **실제 동작**: 백엔드에서 `endTime`이 누락된 대여 데이터에 대해 날짜 차이 계산(`endMs - startMs`) 시 `NaN`이 발생하고, 이 `NaN`이 총 요금 산출식(`baseFare + duration * perMinute`)까지 전파되어 영수증 모달에 `예상 요금: ₩NaN` 또는 `NaN원`으로 표시된다.
6. **재현 절차**:
   - 상단 네비게이션에서 [이용 기록] 클릭
   - `RO-20260928-309` (RideOn Bike 118) 이용 내역 카드 클릭
   - '이용 요금 상세 영수증' 모달 팝업 확인
   - 최종 결제 금액에 `₩NaN` 표시 확인
7. **관련 API**: `GET /api/rentals/:id/fare`
8. **관련 파일**: `server.js`, `src/pages/History.jsx`
9. **오류 원인**: `undefined` 날짜에 대한 `getTime()` 호출로 발생한 `NaN`의 산술 연산 전파
10. **PPO가 관찰할 수 있는 현상**: 영수증 모달의 요금란에 정상적인 원화 금액 대신 `₩NaN` 문자열이 노출됨
11. **기대되는 탐색 trajectory**:
    ```text
    이용 기록 → RO-20260928-309 내역 클릭 → 요금 산정 내역 모달 열람 → ₩NaN 요금 확인
    ```

## 3. site057-SEC-463: Array.sort()의 원본 배열 변형으로 목록 순서가 다른 화면까지 변경되는 오류

1. **Bug ID**: `site057-SEC-463`
2. **오류 유형**: `Shared State` (`mutating-sort-side-effect`)
3. **발생 조건**: 주변 차량(`Nearby.jsx`) 페이지에서 정렬 필터를 '배터리 높은순'으로 변경한 후 홈 화면으로 이동할 때
4. **정상 동작**: 주변 차량 목록의 정렬 변경은 해당 페이지 내에서만 적용되어야 하며, 홈 화면의 추천 차량 목록 순서에는 영향을 주지 않아야 한다.
5. **실제 동작**: `Nearby.jsx`에서 `[...vehicles]` 복사본을 생성하지 않고 공유되는 `vehicles` 원본 배열에 직접 `vehicles.sort(...)`를 수행하여, 홈 화면의 '추천 인기 모빌리티' 순서까지 배터리 정렬 순서로 영구 변경되는 부작용이 발생한다.
6. **재현 절차**:
   - [홈] 화면에서 '추천 인기 모빌리티'의 첫 번째 차량(RideOn Bike 102) 확인
   - 상단 [주변 차량] 메뉴 이동
   - 목록 정렬 기준을 [배터리 높은순]으로 변경
   - 상단 로고를 눌러 [홈] 화면으로 복귀
   - 홈 화면의 '추천 인기 모빌리티' 첫 번째 차량이 배터리 98%인 'RideOn Bike 220'으로 바뀐 것 확인
7. **관련 API**: `GET /api/vehicles`
8. **관련 파일**: `src/pages/Nearby.jsx`, `src/pages/Home.jsx`
9. **오류 원인**: JavaScript `Array.prototype.sort()`의 in-place mutation(원본 배열 직접 수정) 특성
10. **PPO가 관찰할 수 있는 현상**: 다른 페이지에서 정렬을 바꿨을 뿐인데 홈 화면의 추천 차량 순서가 뒤바뀌는 Side Effect 관찰
11. **기대되는 탐색 trajectory**:
    ```text
    홈(추천 차량 순서 확인) → 주변 차량 이동 → '배터리 높은순' 선택 → 홈 이동 → 추천 차량 목록 순서 변형 관찰
    ```

## 4. site057-SEC-464: 날짜 포맷 YYYY-MM-DD와 locale 포맷을 잘못 혼합하는 오류

1. **Bug ID**: `site057-SEC-464`
2. **오류 유형**: `Date Formatting` (`date-format-token-mismatch`)
3. **발생 조건**: 이용 기록 목록에서 1자리 수 월/일 데이터(예: 9월 8일, 9월 1일 등)를 조회할 때
4. **정상 동작**: 모든 이용 기록 날짜가 `YYYY-MM-DD` 형식(예: `2026-09-08`, `2026-09-01`)으로 일관되게 표시되어야 한다.
5. **실제 동작**: 백엔드 `GET /api/rides/history`에서 날짜 문자열 포맷팅 시 `padStart(2, '0')` 없이 `${d.getFullYear()}-${d.getMonth() + 1}-${d.getDate()}`로 단순 결합하여, `2026-09-08`이 `2026-9-8`로 비정상 포맷팅되어 반환된다.
6. **재현 절차**:
   - 상단 네비게이션에서 [이용 기록] 클릭
   - 4번째 항목(`RO-20260908-412`) 및 5번째 항목(`RO-20260901-501`)의 날짜 표시 확인
   - `2026-9-8`, `2026-9-1`과 같이 2자리 패딩이 누락된 날짜 문자열 확인
7. **관련 API**: `GET /api/rides/history`
8. **관련 파일**: `server.js`, `src/components/RideHistoryCard.jsx`
9. **오류 원인**: 날짜 포맷팅 시 두 자리 패딩 로직 누락으로 인한 포맷 토큰 불일치
10. **PPO가 관찰할 수 있는 현상**: 다른 항목(`2026-09-28`)과 달리 특정 날짜에서 0이 빠진 불균형한 날짜 텍스트 노출
11. **기대되는 탐색 trajectory**:
    ```text
    이용 기록 → 목록 스크롤 → 2026-9-8, 2026-9-1 날짜 형식 불일치 관찰
    ```

## 5. site057-SEC-465: CSS pointer-events로 버튼 클릭이 보이지 않는 overlay에 가로막히는 오류

1. **Bug ID**: `site057-SEC-465`
2. **오류 유형**: `UI Interaction` (`invisible-overlay-blocking`)
3. **발생 조건**: 차량 목록에서 [대여하기]를 눌러 대여 확인 모달이 열렸을 때 [대여 시작] 버튼을 클릭할 때
4. **정상 동작**: [대여 시작] 버튼 클릭 시 모달이 닫히고 대여 세션이 정상 시작되어 주행 화면으로 전환되어야 한다.
5. **실제 동작**: 모달 버튼 영역 상단에 투명한 오버레이(`position: absolute; inset: 0; opacity: 0; pointer-events: auto;`)가 남아있어 버튼 클릭 이벤트가 버튼에 도달하지 못하고 가로채어져 아무런 반응이 없다.
6. **재현 절차**:
   - [주변 차량] 또는 [홈] 화면에서 임의 차량의 [대여하기] 버튼 클릭
   - 'RideOn 대여 확인' 모달 팝업 표시
   - 하단의 초록색 [대여 시작] 버튼 클릭
   - 버튼이 눌려도 클릭 이벤트가 실행되지 않고 모달이 그대로 멈춰있는 현상 확인
7. **관련 API**: `POST /api/rentals` (트리거되지 않음)
8. **관련 파일**: `src/pages/Rental.jsx`
9. **오류 원인**: 마우스 이벤트를 흡수하는 투명 오버레이 레이어의 잔류
10. **PPO가 관찰할 수 있는 현상**: 버튼이 비활성화(disabled) 상태가 아님에도 클릭 시 아무런 반응이 없는 먹통 현상
11. **기대되는 탐색 trajectory**:
    ```text
    차량 선택 → 대여하기 → 대여 확인 모달 → '대여 시작' 클릭 → 버튼 클릭 무반응 관찰
    ```
