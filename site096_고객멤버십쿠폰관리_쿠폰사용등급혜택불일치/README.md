## 📋 정상 기능 요약

- **멤버십 등급 체계 현황**: BRONZE, SILVER, GOLD, VIP, VVIP 5단계 등급 할인율 및 적립률 관제.
- **고객 대장 & 혜택 조회**: 35명의 회원 고객 인적사항, 누적 구매액, 보유 포인트, 선호 매장 조회.
- **쿠폰 발급 및 포인트 관리**: 40개 쿠폰 발급/사용 내역 관리 및 60건의 포인트 적립/차감 이력 조회.
- **고객 구매 이력 & 감사 로그**: 50건의 매장별 결제 이력 및 CRM 운영자 활동 감사 로그 제공.

## ⚠️ 의도적으로 삽입된 8가지 복합 오류 목록

1. **Frontend + Backend 요청 순서 충돌**
   - **설명**: 고객 등급을 변경(3초 지연 완료)한 직후 쿠폰을 발급(0.1초 완료)하면, 쿠폰 발급 API는 먼저 완료되나 3초 뒤 완료되는 등급 변경 API가 요청 시작 시점의 구 DB 스냅샷(이전 등급)을 덮어써 저장하여 새로고침 시 쿠폰 혜택률은 이전 등급 기준이고, 고객 카드 등급은 새 등급처럼 불일치하게 보입니다.

2. **Backend + JSON DB 상태 충돌**
   - **설명**: 쿠폰 사용 취소 API(0.5초 완료)를 호출한 직후 포인트 적립 API를 호출(4초 지연 완료)하면, 쿠폰 사용 취소는 성공하지만 늦게 완료된 포인트 적립 요청이 취소된 쿠폰을 다시 'USED'(사용완료) 상태로 변경합니다. 고객 쿠폰 목록에서는 사용취소, 포인트 내역에서는 사용완료 쿠폰 혜택 적립으로 서로 불일치합니다.

3. **Frontend 정렬 인덱스 오류**
   - **설명**: 고객 목록을 누적 구매금액순/포인트순으로 정렬한 뒤 쿠폰 발급 버튼을 누르면 화면 알림은 클릭한 고객명으로 뜨지만 backend 저장 데이터는 원본 정렬 전 배열의 다른 고객 ID에 연결되어 쿠폰이 발급됩니다.

4. **통계 집계 불일치**
   - **설명**: 쿠폰 사용 내역을 삭제(`DELETE /api/coupons/:id/usage`) 처리하여 쿠폰 목록에서 소거하더라도, 대시보드 쿠폰 사용률(`membershipStats.couponUsageRate`), 등급별 혜택 금액, 월별 프로모션 통계 수치에는 차감되지 않고 계속 잔존합니다.

5. **Network stale response 오류**
   - **설명**: 등급 필터('VVIP' 3초 지연 ➔ 'GOLD' 0.2초 완료)와 쿠폰 필터를 빠르게 변경 시 오래된 응답(VVIP)이 최신 고객 목록을 덮어써 고객 목록은 오래된 필터 결과, 오른쪽 혜택 요약은 최신 필터 기준 수치로 서로 불일치합니다.

6. **Session + Cache 잔존 오류**
   - **설명**: 관리자 A가 고객 상세를 본 뒤 관리자 B로 로그인하면 고객 목록은 B 기준으로 바뀌지만, 상단 오늘 발급 쿠폰 수 및 최근 관리 고객 상세 요약 캐시(`cachedCouponCount`, `cachedRecentCustomer`)는 A 데이터가 남아 노출됩니다.

7. **Backend 권한 로그 오류**
   - **설명**: 권한 없는 일반 사원(role !== 'ADMIN')이 등급 강등 API(`PATCH /api/customers/:id/tier/downgrade`)를 호출하면 HTTP 403을 반환하지만, 서버 내부 활동 로그에는 '등급 강등 성공 (CUSTOMER TIER DOWNGRADED SUCCESSFULLY - 200 OK)'으로 잘못 기록됩니다.

8. **부분 저장 오류**
   - **설명**: 고객 정보 수정 모달/패널에서 연락처, 선호 매장, 마케팅 수신 여부를 동시에 수정하면 백엔드 data.json에는 연락처와 마케팅 수신 여부만 저장되고 선호 매장은 이전 값을 유지하지만, 프론트엔드는 세 항목 모두 수정 성공한 것으로 표시합니다.

## 🧪 테스트 시나리오

1. **Error 1 테스트**: 우측 관제 패널에서 등급 변경 선택 후 `등급 변경 후 즉시 쿠폰 발급 (Error 1)` 클릭 ➔ 0.1초 후 쿠폰 발급 응답 ➔ 3초 후 등급 변경 응답 완료 ➔ 새로고침 시 쿠폰 혜택률이 이전 등급 기준 할인율로 롤백 저장됨을 확인.
2. **Error 2 테스트**: 우측 관제 패널에서 `⚡ 쿠폰 사용 취소 후 포인트 적립 (Error 2)` 클릭 ➔ 0.5초 후 쿠폰 사용 취소 응답 ➔ 4초 후 포인트 적립 응답 완료 ➔ 취소된 쿠폰이 다시 USED 상태로 재활성화됨을 확인.
3. **Error 3 테스트**: 좌측 사이드바에서 `누적 구매금액 높은순` 정렬 선택 ➔ 최상단 고객의 `쿠폰발급` 클릭 ➔ UI 상단 고객명과 우측 관제 패널의 고객 ID/정보가 상이함을 확인.
4. **Error 4 테스트**: 중앙 쿠폰 대장에서 `🗑️ 쿠폰 내역 삭제` 클릭 ➔ 대장에서는 삭제되나 대시보드 쿠폰 사용률 및 혜택 수치가 유지됨을 확인.
5. **Error 5 테스트**: 좌측 등급 필터를 `VVIP 등급` 선택 직후 `GOLD 등급` 선택 ➔ 3초 후 늦은 이전 VVIP 결과가 최신 GOLD 고객 목록을 덮어씀을 확인.
6. **Error 6 테스트**: 상단 로그인 운영자를 `김멤버십 (CRM 팀장)`에서 `이쿠폰 (과장)`으로 전환 ➔ 고객 목록은 B로 바뀌나 상단 KPI 금일 발급 쿠폰 건수는 A 데이터로 잔존함을 확인.
7. **Error 7 테스트**: 상단 계정을 일반 사원으로 테스트 시 `🔒 일반 사원의 강제 등급 강등 시도` 클릭 ➔ UI/API는 HTTP 403 오류 반환 ➔ 백엔드 콘솔 로그에는 SUCCESS (200 OK)로 잘못 작성됨을 확인.
8. **Error 8 테스트**: 우측 하단 고객 정보 수정 패널에서 선호 매장 포함 입력 후 `고객 정보 저장` 클릭 ➔ 토스트는 성공으로 표시되나 새로고침 시 선호 매장만 수정되지 않았음을 확인.
