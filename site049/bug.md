### SEC-421: 로그아웃 후 이전 세션 UI 상태 잔존
* **SEC ID:** `SEC-421`
* **오류 이름:** 로그아웃 후 이전 세션 UI 상태 잔존
* **오류 유형:** authentication / stale-session-state
* **발생 조건:** 로그인 상태에서 사용자가 헤더의 [로그아웃] 버튼을 클릭했을 때
* **정상 동작:** 로그아웃 시 서버 세션이 종료되고 프론트엔드의 사용자 프로필, 참여 내역, 알림 등이 즉시 비로그인 상태로 초기화되어야 함
* **현재 동작:** 서버의 세션은 null로 해제되지만 클라이언트 전역 상태가 즉시 초기화되지 않아 화면상에 이전 사용자의 이름과 프로필이 유지됨
* **관련 API:** `POST /api/auth/logout`
* **관련 UI:** Header 프로필 영역, MyActivities 페이지, 로그아웃 버튼
* **관찰 가능한 결과:** 로그아웃 알림 후에도 헤더에 사용자 이름이 남아있고 참여 내역이 일시적으로 조회 가능함
* **PPO 탐색 흐름:** `로그인 확인` → `로그아웃 클릭` → `페이지 네비게이션` → `DOM 내 사용자 정보 잔존 탐색`

### SEC-422: 페이지 번호와 실제 데이터 불일치
* **SEC ID:** `SEC-422`
* **오류 이름:** 봉사활동 목록 페이지 번호와 실제 데이터 오프셋 불일치
* **오류 유형:** pagination / offset-state-mismatch
* **발생 조건:** 봉사활동 목록 페이지에서 2페이지 또는 그 이상의 페이지 번호 버튼을 클릭할 때
* **정상 동작:** 선택한 페이지 번호에 해당하는 새로운 봉사활동 목록 데이터가 화면에 렌더링되어야 함
* **현재 동작:** UI 상에서는 2페이지가 활성화되나 실제 API 요청 시 이전 페이지 오프셋을 재사용하여 1페이지의 활동들이 다시 표시됨
* **관련 API:** `GET /api/activities?page=2&limit=6`
* **관련 UI:** Activities 페이지 하단 Pagination 컴포넌트
* **관찰 가능한 결과:** 2페이지를 클릭했음에도 1페이지와 동일하거나 어긋난 봉사활동 카드 목록이 표시됨
* **PPO 탐색 흐름:** `봉사활동 목록 조회` → `2페이지 클릭` → `페이지 번호 상태와 목록의 첫 번째 아이템 ID 비교`

### SEC-423: 날짜 및 시간대 표시 불일치
* **SEC ID:** `SEC-423`
* **오류 이름:** 활동 일정의 UTC / 로컬 타임존 변환 표기 불일치
* **오류 유형:** datetime / timezone-display
* **발생 조건:** 101번(우리 동네 공원 플로깅) 또는 106번 봉사활동 상세 페이지 진입 시
* **정상 동작:** 목록 페이지와 상세 페이지에서 동일한 활동 시작 시간(예: 10:00)이 일관되게 표시되어야 함
* **현재 동작:** 서버에서 UTC 기준으로 전달된 시각 문자열을 상세 페이지에서 잘못 변환하여 01:00 또는 09:00으로 다르게 표시됨
* **관련 API:** `GET /api/activities/:id`
* **관련 UI:** ActivityDetail 페이지 일정 카드, ActivityCard 일정 뱃지
* **관찰 가능한 결과:** 카드에서는 10:00으로 보이나 상세 페이지에서는 다른 시간대 또는 UTC 기준 시간이 노출됨
* **PPO 탐색 흐름:** `목록에서 시간 확인(10:00)` → `상세 진입` → `상세 페이지의 표시 시간 불일치 탐색`

### SEC-424: 참여 신청 중복 요청 처리 실패
* **SEC ID:** `SEC-424`
* **오류 이름:** 동일 봉사활동에 대한 중복 참여 신청 생성
* **오류 유형:** concurrency / duplicate-request
* **발생 조건:** 봉사활동 상세 페이지에서 이미 신청한 상태에서 '참여 신청'을 다시 누르거나 빠르게 연속 클릭 시
* **정상 동작:** 이미 신청한 사용자에게는 '이미 신청된 활동입니다' 메시지를 반환하거나 중복 신청을 차단해야 함
* **현재 동작:** 서버에서 기존 신청 여부를 확인하지 않고 매 요청마다 새로운 enrollment ID를 발급하여 중복 신청 레코드가 누적됨
* **관련 API:** `POST /api/activities/:id/join`
* **관련 UI:** ActivityDetail [참여 신청] 버튼, MyActivities [참여 내역]
* **관찰 가능한 결과:** 참여 내역 페이지에 동일한 봉사활동 항목이 여러 개 등록되어 있음
* **PPO 탐색 흐름:** `활동 상세 진입` → `참여 신청 클릭` → `참여 신청 재클릭` → `참여 내역에서 중복 레코드 확인`

### SEC-425: 알림 읽음 상태의 데이터 최신성 불일치
* **SEC ID:** `SEC-425`
* **오류 이름:** 알림 읽음 처리 후 프론트엔드 캐시 잔존으로 인한 최신성 불일치
* **오류 유형:** data-consistency / stale-cache
* **발생 조건:** 알림 목록에서 특정 알림의 '읽음' 버튼을 누르거나 알림을 확인했을 때
* **정상 동작:** 서버 및 클라이언트 모두에서 해당 알림이 즉시 읽음 처리되고 상단 알림 뱃지 카운트가 감소해야 함
* **현재 동작:** 서버에서는 read=true로 갱신되었으나 프론트엔드의 캐시된 알림 목록 상태가 즉시 갱신되지 않아 화면에 unread 뱃지가 유지됨
* **관련 API:** `PATCH /api/notifications/:id/read`
* **관련 UI:** Header 알림 드롭다운, Notifications 페이지
* **관찰 가능한 결과:** 읽음으로 표시를 눌러도 알림 아이콘의 빨간 뱃지가 사라지지 않고 남아있음
* **PPO 탐색 흐름:** `알림 목록 확인` → `읽음 버튼 클릭` → `타 페이지 이동 후 헤더 알림 뱃지 카운트 불일치 탐색`
