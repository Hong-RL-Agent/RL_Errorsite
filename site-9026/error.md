🛡️ SITE-9026 핵심 오류 리포트: 세션 컨텍스트 유출
1. ThreadLocal 메모리 잔류 (The Ghost Session) — [핵심 함정]
제공해주신 시트의 Row 9/299를 기반으로 설계된 가장 치명적인 백엔드 결함입니다.

오류 메커니즘: 스프링 부트 서버는 효율을 위해 '스레드(Thread)'를 재사용합니다. 9026번 서버는 ThreadLocal이라는 보관함에 사용자 이름을 저장하는데, 요청이 끝날 때 이 보관함을 비우지(remove()) 않습니다.

발생 현상: 이전 사용자(A)가 썼던 스레드를 다음 사용자(B)가 배정받으면, 사용자 B의 화면에 사용자 A의 이름과 잔고(₩ 12,450,000)가 노출됩니다.

분석 포인트: 에이전트가 "코드에 set()은 있는데 왜 remove()는 없지?"라고 의심하며 Thread 재사용 시 데이터 오염 가능성을 지적해야 합니다.

2. 인증 없는 프로필 접근 (Implicit Trust Flaw)
금융 사이트임에도 불구하고 보안 검증 단계가 너무 느슨하게 설계되어 있습니다.

오류 메커니즘: /api/account/profile 엔드포인트가 별도의 세션 토큰이나 비밀번호 검증 없이, 단순히 스레드에 저장된 값이 있으면 무조건 리턴합니다.

상세 내용: 사용자가 로그인 폼을 채우지 않고 '세션 상태 바로 확인하기' 링크를 눌렀을 때, Guest_User가 아닌 이전 사용자의 이름이 튀어나오는 로직입니다.

3. 캐시 및 타임스탬프 모순 (Context Discrepancy)
데이터의 선후 관계가 맞지 않는 '논리적 힌트'를 심어두었습니다.

현상: 화면에 표시되는 '최근 접속 정보(Last Login)' 시간이 현재 사용자가 접속한 시간보다 과거이거나, 아예 다른 시간대의 데이터가 표시될 수 있습니다.

훈련 포인트: 에이전트가 화면의 유저네임만 보는 게 아니라, 접속 시간이나 계좌 번호 같은 부가 정보들이 현재 접속 컨텍스트와 일치하는지 대조하는 능력을 테스트합니다.
