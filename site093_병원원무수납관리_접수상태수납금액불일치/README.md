## 📋 정상 기능 요약

- **원무 접수 번호표 대기열 워크플로우**: 40개 이상의 접수 ➔ 진료대기 ➔ 수납 ➔ 완료 단계별 워크플로우 관제.

- **원무 직원 활동 및 감사 로그**: 60개 이상의 직원별 수납, 접수, 변경 이력 감사 로그 제공.
- **진료과 및 환자 인적사항 관리**: 8개 진료과 배정, 진료비 수납금액 수정, 환자 정보 관리.

## ⚠️ 의도적으로 삽입된 8가지 복합 오류 목록

1. **Frontend + Backend 요청 순서 충돌**
   - **설명**: 접수 진료과를 변경(3초 지연 완료)한 직후 수납 금액을 수정(0.1초 완료)하면, 수납 금액 수정 API는 먼저 완료되나 3초 뒤 완료되는 진료과 변경 API가 요청 시작 시점의 구 DB 스냅샷(이전 진료과)을 덮어써 저장하여 새로고침 시 접수 목록과 수납 상세의 진료과가 서로 달라집니다.

2. **Backend + JSON DB 상태 충돌**
   - **설명**: 접수 취소 API(0.5초 완료)를 호출한 직후 수납 완료 API를 호출(4초 지연 완료)하면, 접수 취소는 먼저 성공하지만 늦게 완료된 수납 완료 요청이 취소된 접수를 'COMPLETED'(수납완료) 상태로 다시 바꿔버립니다. 접수 대기열에서는 취소됨, 수납 내역에서는 완료로 표시됩니다.

3. **Frontend 정렬 인덱스 오류**
   - **설명**: 접수 대기열을 대기시간순/수납금액순으로 정렬한 뒤 상세보기 버튼을 누르면 화면 상단 환자명은 클릭한 환자명으로 표시되나 우측 관제 패널의 접수번호와 수납 금액은 원본 정렬 전 배열의 다른 환자 기준 데이터가 노출됩니다.

4. **통계 집계 불일치**
   - **설명**: 수납 내역을 삭제(`DELETE /api/payments/:id`) 처리하여 수납 목록에서 소거하더라도, 일일 매출 합계(`clinicStats.totalRevenue`), 진료과별 수납 통계, 직원별 처리량 수치에는 차감되지 않고 계속 유지됩니다.

5. **Network stale response 오류**
   - **설명**: 진료과 필터('내과' 3초 지연 ➔ '정형외과' 0.2초 완료)와 접수 상태를 빠르게 변경 시 오래된 응답이 최신 목록을 덮어써 중앙 대기열은 오래된 필터 결과, 오른쪽 수납 요약은 최신 필터 기준 수치로 서로 불일치합니다.

6. **Session + Cache 잔존 오류**
   - **설명**: 직원 A가 환자 상세를 본 뒤 직원 B로 로그인하면 접수 목록은 B 기준으로 바뀌지만, 상단 처리 건수 및 최근 환자 상세 요약 캐시(`cachedCount`, `cachedRecentPatient`)는 A 데이터가 남아 노출됩니다.

7. **Backend 권한 로그 오류**
   - **설명**: 권한 없는 직원(role !== 'ADMIN')이 수납 취소 API(`POST /api/payments/:id/cancel`)를 호출하면 HTTP 403을 반환하지만, 서버 내부 활동 로그에는 '수납 취소 성공 (PAYMENT CANCELLED SUCCESSFULLY - 200 OK)'으로 잘못 기록됩니다.

8. **부분 저장 오류**
   - **설명**: 환자 정보 수정 모달/패널에서 연락처, 주소, 보호자 이름을 동시에 수정하면 백엔드 data.json에는 연락처와 주소만 저장되고 보호자 이름은 이전 값을 유지하지만, 프론트엔드는 세 항목 모두 수정 성공한 것처럼 표시합니다.

## 🧪 테스트 시나리오

1. **Error 1 테스트**: 우측 관제 패널에서 진료과 변경 입력 후 `수납금 수정 (Error 1)` 클릭 ➔ 0.1초 후 금액 수정 응답 ➔ 3초 후 진료과 변경 응답 완료 ➔ 새로고침 시 진료과가 이전 진료과로 롤백 저장됨을 확인.
2. **Error 2 테스트**: 우측 관제 패널에서 `⚡ 접수 취소 후 수납 완료 승인` 클릭 ➔ 0.5초 후 접수 취소 응답 ➔ 4초 후 수납 완료 응답 완료 ➔ 접수가 취소됨에서 다시 COMPLETED (수납완료) 상태로 재활성화됨을 확인.
3. **Error 3 테스트**: 좌측 사이드바에서 `대기시간 긴 순` 정렬 선택 ➔ 최상단 환자의 상세보기 클릭 ➔ UI 상단 환자명과 우측 관제 패널의 접수번호/수납금액 정보가 상이함을 확인.
4. **Error 4 테스트**: 중앙 진료비 수납 내역 대장에서 `🗑️ 수납 내역 삭제` 클릭 ➔ 대장에서는 삭제되나 대시보드 매출 합계 및 진료과별 수납 통계 수치가 유지됨을 확인.
5. **Error 5 테스트**: 좌측 진료과 필터를 `내과` 선택 직후 `정형외과` 선택 ➔ 3초 후 늦은 이전 내과 결과가 최신 정형외과 접수 대기열을 덮어씀을 확인.
6. **Error 6 테스트**: 상단 로그인 직원을 `김원무 (수석계장)`에서 `이수납 (수납과장)`으로 전환 ➔ 접수 목록은 B로 바뀌나 상단 KPI 처리 건수는 A 데이터로 잔존함을 확인.
7. **Error 7 테스트**: 상단 계정을 `박접수 (접수주임)`로 전환 후 `🔒 일반 사원의 강제 수납 취소 시도` 클릭 ➔ UI/API는 HTTP 403 오류 반환 ➔ 백엔드 콘솔 로그에는 SUCCESS (200 OK)로 잘못 작성됨을 확인.
8. **Error 8 테스트**: 우측 하단 환자 정보 수정 패널에서 보호자 이름 포함 입력 후 `환자 정보 저장` 클릭 ➔ 토스트는 성공으로 표시되나 새로고침 시 보호자 이름만 수정되지 않았음을 확인.
