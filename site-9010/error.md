🏗️ Site #9010 장애 요소 요약
이번 사이트는 '고급스러운 UI' 뒤에 설계 결함이 숨어있는 "Hanging(응답 없음)" 시나리오가 핵심입니다.

1. 벌크 액션을 통한 자원 고갈 (Resource Exhaustion)
파일: backend/server.js

내용: 사용자 5만 명에게 메일을 보내는 대량 작업을 수행할 때, 내부적으로 엄청난 횟수의 루프(8억 번)를 메인 스레드에서 직접 돌립니다.

오류 성격: CSV 리스트 5번 항목인 자원 고갈입니다. CPU 점유율을 순식간에 100%까지 끌어올려 다른 모든 작업을 마비시킵니다.

2. 이벤트 루프 차단 (Event Loop Blocking)
기술적 원인: Node.js는 싱글 스레드 기반이라 한 번에 하나의 작업만 할 수 있습니다. 메일 발송 로직이 비동기(Queue나 Worker Thread)가 아닌 **동기적(Synchronous)**으로 작성되어 있어, 이 작업이 끝날 때까지 서버는 들어오는 어떤 요청(메뉴 클릭, 상태 조회 등)에도 응답하지 못합니다.

현상: 사용자가 버튼을 누르면 브라우저가 무한 대기에 빠지고, 다른 탭으로 메뉴를 옮기려고 해도 화면이 멈춘 것처럼 느껴집니다.

3. 서비스 거부(DoS) 유발 (Internal Denial of Service)
결과: 외부의 공격이 아닌, 정상적인 관리자 기능 하나가 시스템 전체를 다운시키는 결과를 초래합니다.

학습 목표: 에이전트(J.A.W.S)는 "단순히 서버가 죽은 게 아니라, 특정 요청이 서버의 스레드를 점유하고 있구나!"라는 것을 docker stats의 CPU 수치나 로그 분석을 통해 진단해야 합니다.
