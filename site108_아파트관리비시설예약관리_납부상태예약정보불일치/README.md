## 📋 정상 기능 요약

- **아파트 세대별 관리비 고지 & 납부 대장**: 60건의 당월 관리비 청구 내역(미납/납부완료) 및 40세대 입주민 정보 관제.
- **공용시설 예약 캘린더**: 45건의 5대 공용시설(헬스장, 독서실, 게스트룸, 커뮤니티룸, 주차장) 이용 예약 및 인원 관제.
- **입주민 민원 접수대 & 감사 로그**: 35건의 입주민 민원 처리 현황 및 80건의 시설 이용/수납 활동 감사 로그 관리.
- **관리사무소 통합 관제**: 관리소장(MANAGER)/스태프(STAFF) 권한 관리 및 세대 차량 등록 관리.

## ⚠️ 의도적으로 삽입된 8가지 복합 오류 목록

1. **Frontend + Backend 요청 순서 충돌**
   - **설명**: 시설 예약 시간을 변경(3초 지연 완료)한 직후 이용 인원을 변경(0.1초 완료)하면, 이용 인원 변경 API는 먼저 완료되나 3초 뒤 완료되는 시간 변경 API가 요청 시작 시점의 구 DB 스냅샷(이전 인원)을 덮어써 저장하여 새로고침 시 예약 목록과 예약 상세의 이용 인원이 서로 달라집니다.

2. **Backend + JSON DB 상태 충돌**
   - **설명**: 시설 예약 취소 API(0.5초 완료)를 호출한 직후 관리비 납부 상태 갱신 API를 호출(4초 지연 완료)하면, 예약 취소는 성공하지만 늦게 완료된 납부 상태 갱신 요청이 취소된 시설 예약을 다시 CONFIRMED 예약완료 상태로 복원시킵니다. 내 예약에서는 취소됨, 관리사무소 시설 현황에서는 예약완료로 표시됩니다.

3. **Frontend 정렬 인덱스 오류**
   - **설명**: 민원 목록을 처리기한순/긴급도순으로 정렬한 뒤 상세 버튼을 누르면 UI 알림은 클릭한 민원 제목으로 뜨지만, 백엔드 저장 데이터는 정렬 전 원본 배열의 다른 민원 ID에 연결되는 결함입니다.

4. **통계 집계 불일치**
   - **설명**: 시설 예약 로그를 삭제(`DELETE /api/reservation-logs/:id`) 처리하여 로그 목록에서 소거하더라도, 시설별 이용률(`aptStats.facilityUsageRate`), 세대별 예약 횟수, 월별 예약 통계 수치에는 차감되지 않고 계속 잔존합니다.

5. **Network stale response 오류**
   - **설명**: 동 번호 필터('101동' 3초 지연 ➔ '102동' 0.2초 완료)와 시설 유형 필터를 빠르게 변경 시 오래된 응답(101동)이 최신 예약 목록을 덮어써 예약 목록은 오래된 필터 결과, 오른쪽 시설 요약은 최신 필터 기준 수치로 서로 불일치합니다.

6. **Session + Cache 잔존 오류**
   - **설명**: 입주민 A가 관리비 상세를 본 뒤 입주민 B로 로그인하면 관리비 목록은 B 세대 기준으로 바뀌지만, 상단 미납 금액 및 최근 시설 예약 캐시(`cachedUnpaidAmount`, `cachedRecentBooking`)는 A 데이터가 남아 노출됩니다.

7. **Backend 권한 로그 오류**
   - **설명**: 권한 없는 직원(role !== 'MANAGER')이 관리비 납부완료 API(`POST /api/bills/:id/pay-unauthorized`)를 호출하면 HTTP 403을 반환하지만, 서버 내부 활동 로그에는 '관리비 납부완료 성공 (MAINTENANCE BILL PAID SUCCESSFULLY - 200 OK)'으로 잘못 기록됩니다.

8. **부분 저장 오류**
   - **설명**: 세대 정보 수정 모달/패널에서 연락처, 차량번호, 입주민 메모를 동시에 수정하면 백엔드 data.json에는 연락처와 입주민 메모만 저장되고 차량번호는 이전 값을 유지하지만, 프론트엔드는 세 항목 모두 수정 성공한 것으로 표시합니다.

## 🧪 테스트 시나리오

1. **Error 1 테스트**: 우측 관제 패널에서 예약 시간대 변경 선택 후 `예약 시간 변경 후 즉시 이용 인원 변경 (Error 1)` 클릭 ➔ 0.1초 후 인원 변경 응답 ➔ 3초 후 시간 변경 응답 완료 ➔ 새로고침 시 이전 인원으로 롤백 저장됨을 확인.
2. **Error 2 테스트**: 우측 관제 패널에서 `⚡ 시설 예약 취소 후 관리비 납부 갱신 연쇄 실행 (Error 2)` 클릭 ➔ 0.5초 후 예약 취소 응답 ➔ 4초 후 납부 갱신 응답 완료 ➔ 취소된 예약이 CONFIRMED 예약완료 상태로 복원됨을 확인.
3. **Error 3 테스트**: 좌측 사이드바에서 `처리기한 마감순` 정렬 선택 ➔ 최상단 민원의 `상세` 클릭 ➔ UI 상단 민원 제목과 우측 관제 패널의 세대/메모 정보가 상이함을 확인.
4. **Error 4 테스트**: 중앙 활동 감사 로그 대장에서 `🗑️ 로그 삭제` 클릭 ➔ 대장에서는 삭제되나 대시보드 시설 이용률 수치가 유지됨을 확인.
5. **Error 5 테스트**: 좌측 동 필터를 `101동` 선택 직후 `102동` 선택 ➔ 3초 후 늦은 이전 101동 결과가 최신 102동 예약 목록을 덮어씀을 확인.
6. **Error 6 테스트**: 상단 로그인 입주 세대를 `101동 101호`에서 `101동 102호`로 전환 ➔ 관리비 목록은 B로 바뀌나 상단 KPI 미납 금액은 A 데이터로 잔존함을 확인.
7. **Error 7 테스트**: 상단 계정을 일반 스태프 직원으로 테스트 시 `🔒 권한 없는 일반 직원의 관리비 강제 납부완료 처리 시도` 클릭 ➔ UI/API는 HTTP 403 오류 반환 ➔ 백엔드 콘솔 로그에는 SUCCESS (200 OK)로 잘못 작성됨을 확인.
8. **Error 8 테스트**: 우측 하단 세대 정보 수정 패널에서 차량번호 포함 입력 후 `세대 정보 저장` 클릭 ➔ 토스트는 성공으로 표시되나 새로고침 시 차량번호만 수정되지 않았음을 확인.
