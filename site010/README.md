# Digital Wallet Platform (site010)

## 개요
- **사이트 ID**: site010
- **포트 번호**: 9119
- **기술 스택**: React + Vite + Express
- **주제**: 디지털 월렛 및 결제 처리 시스템

본 사이트는 PPO 에이전트가 백엔드 API 오류, 서버 응답 오류, 데이터 처리 오류를 탐지하도록 훈련시키기 위한 테스트 환경입니다. 실제 핀테크 대시보드와 같은 UI를 제공하며, 의도된 3가지 백엔드 오류를 포함하고 있습니다.

## 실행 방법
```bash
cd site010
npm install
npm start
```

## API 엔드포인트 목록
- `GET /api/health`: 서버 상태 확인 (항상 정상)
- `GET /api/wallet/balance`: 현재 잔액 조회
- `POST /api/payment/pay`: 결제 요청 처리
- `GET /api/payment/history`: 전체 거래 내역 조회

## 정상 작동 기능 목록
- 대시보드 잔액 실시간 조회
- 최근 거래 내역 리스트 렌더링
- 퀵 페이(₩10,000) 결제 기능
- 로딩 및 에러 상태 처리 UI
- 반응형 레이아웃 (헤더, 푸터, 사이드바 구조)

## 의도된 백엔드 오류 3개
1. **site010-bug01 (null-reference)**
   - **트리거**: 사이드바의 `[BUG] Null Reference Test` 버튼 클릭
   - **설명**: 상세 정보를 포함한 잔액 조회 시 서버 내부의 null 객체를 참조하여 500 에러를 반환합니다.
   - **연결된 data-bug-id**: `site010-bug01`

2. **site010-bug02 (type-parsing)**
   - **트리거**: 사이드바의 `[BUG] Type Parsing Test` 버튼 클릭
   - **설명**: 결제 금액에 잘못된 데이터 타입을 전송하여 서버 측 유효성 검사 실패(422)를 유도합니다.
   - **연결된 data-bug-id**: `site010-bug02`

3. **site010-bug03 (api-timeout)**
   - **트리거**: 사이드바의 `[BUG] API Timeout Test` 버튼 클릭
   - **설명**: 거래 내역 조회 시 의도적으로 7초의 지연을 발생시켜 타임아웃 상황을 재현합니다.
   - **연결된 data-bug-id**: `site010-bug03`

## PPO 에이전트 탐지 기대 행동
- 특정 입력 값이나 파라미터에 따른 서버 응답 코드(500, 422) 변화 감지
- API 응답 속도 지연에 따른 서비스 상태 이상 탐지
- 에러 응답 시 프론트엔드의 UI 변화(에러 배너) 식별
