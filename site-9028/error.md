🚨 SITE-9028: AI Research Hub 핵심 오류 리포트
1. 경쟁 상태로 인한 데이터 유실 (Race Condition / Lost Update)
이번 사이트의 가장 큰 함정입니다. 여러 에이전트나 스레드가 동시에 같은 자원에 접근할 때 발생하는 문제입니다.

오류 메커니즘: 서버가 공유 변수(totalTrainingCount)에 값을 더할 때, 읽기 -> 증가 -> 저장 단계를 거칩니다. 두 스레드가 동시에 값을 '읽기' 단계에서 가로채면, 서로 같은 값을 기반으로 1을 더하게 되어 결국 한 번의 업데이트가 씹히게 됩니다.

발생 현상: 하은님이 프론트엔드에 만들어둔 'RUN_50_BATCH_MODELS' 버튼을 누르면 50개의 요청이 동시에 날아갑니다. 하지만 서버 응답을 보면 50이 아니라 30, 42 등 엉뚱한 숫자가 찍히는 것을 볼 수 있습니다.

에이전트의 미션: "요청 횟수와 결과값이 일치하지 않는다"는 점을 발견하고, 백엔드 코드의 스레드 안전성(Thread-safety) 결여를 지적해야 합니다.

2. 비원자적 연산 (Non-Atomic Operation)
프로그래밍적인 관점에서의 결함입니다.

오류 메커니즘: 백엔드에서 int 타입을 사용하고 아무런 동기화(synchronized) 처리를 하지 않았습니다. 자바에서 count++ 혹은 count = count + 1은 원자적(Atomic)이지 않은 연산입니다.

분석 포인트: 에이전트가 코드를 분석할 때, "왜 AtomicInteger를 쓰지 않았나?" 혹은 "왜 synchronized 블록이 없나?"라고 기술적인 원인을 짚어낼 수 있는지 테스트합니다.

3. 모니터링 데이터의 불일치 (Status Inconsistency)
사용자 경험(UX) 측면의 오류입니다.

현상: 대시보드에는 GPU_LOAD: 88% 같은 정보가 실시간으로 뜨지만, 정작 중요한 TOTAL_TASKS 숫자는 실시간으로 누락되며 신뢰를 잃습니다.

훈련 포인트: 에이전트가 단순한 UI 버그인지, 백엔드 로직의 문제인지 구분해내는 능력을 측정합니다.
