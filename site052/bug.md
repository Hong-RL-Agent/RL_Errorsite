# bug.md — site052 (SpaceMate) 오류 요약

이 문서는 PPO 학습 에이전트 및 평가 파이프라인을 위해 site052에 존재하는 의도적 오류 5개의 핵심 요약 정보를 제공합니다.

---

### SEC-436
* **SEC ID**: SEC-436
* **오류 유형**: 날짜 범위 선택 후 시간 슬롯 UI가 이전 날짜의 상태를 유지하는 문제
* **재현 조건**: 예약 패널에서 날짜 A를 선택하고 특정 시간 슬롯을 클릭한 후, 다른 날짜 B로 변경할 때
* **재현 절차**:
  1. 공간 상세 페이지(`/rooms/:id`)로 이동
  2. 예약 패널에서 첫 번째 날짜 선택 및 특정 시간 슬롯(예: 10:00) 클릭
  3. 날짜 선택기에서 다른 날짜 클릭
  4. 새로 렌더링된 시간 슬롯 목록에서 10:00 슬롯이 여전히 활성화(선택)되어 있는지 확인
* **관찰되는 증상**: 날짜가 바뀌었음에도 이전 날짜의 시간 슬롯 선택 상태가 그대로 유지되어 잘못된 시간으로 예약이 시도될 수 있음
* **정상 동작**: 날짜 변경 시 선택된 시간 슬롯은 초기화되고 새로운 날짜의 예약 현황에 맞춰 다시 선택해야 함
* **오류 발생 원인**: `handleDateChange` 핸들러에서 날짜 state만 업데이트하고 선택된 시간 슬롯 state를 리셋하지 않음
* **PPO가 탐색해야 할 행동**: 날짜 변경 전후의 `selectedTime` 상태 및 시간 슬롯 버튼의 active 클래스 유지 여부 확인

### SEC-437
* **SEC ID**: SEC-437
* **오류 유형**: 모달에서 ESC 키를 눌렀는데 내부 입력값이 초기화되지 않는 문제
* **재현 조건**: 예약 내역의 메모 수정 모달에서 텍스트를 입력/수정한 후 저장하지 않고 ESC 키를 눌러 모달을 닫을 때
* **재현 절차**:
  1. 내 예약 목록(`/bookings`)으로 이동
  2. 특정 예약 항목의 "메모 수정" 버튼 클릭
  3. 텍스트 입력란에 새 메모 내용 입력 (예: "고객 미팅 준비")
  4. 키보드의 `Escape` 키를 눌러 모달 닫기
  5. 동일한 예약의 "메모 수정" 버튼을 다시 클릭하여 모달 열기
  6. 입력창에 저장되지 않고 취소되었어야 할 텍스트가 남아 있는지 확인
* **관찰되는 증상**: 취소(ESC) 후 재오픈 시 이전 수정 중이던 draft 문자열이 그대로 노출됨
* **정상 동작**: ESC 키 입력 시 수정 중이던 draft 내용은 폐기되고 원래 예약 메모 데이터로 리셋되어야 함
* **오류 발생 원인**: ESC 키 다운 리스너에서 모달 visible 상태만 닫고 내부 폼 state를 이전 값으로 복원하지 않음
* **PPO가 탐색해야 할 행동**: 모달 내 텍스트 수정 -> ESC 입력 -> 모달 재열기 -> draft 잔존 여부 확인

### SEC-438
* **SEC ID**: SEC-438
* **오류 유형**: 즐겨찾기 토글의 optimistic UI 실패 후 원래 상태로 복구되지 않는 문제
* **재현 조건**: `room-018` 공간 카드에서 즐겨찾기(하트) 버튼을 클릭할 때
* **재현 절차**:
  1. 공간 목록(`/rooms`) 또는 공간 상세 페이지 진입
  2. ID가 `room-018`인 공간(Creator Atelier 02)의 즐겨찾기 버튼 클릭
  3. UI가 즉시 즐겨찾기 등록(♥)으로 변경됨
  4. 백엔드에서 500 에러 응답 수신
  5. 화면의 하트 상태가 이전(♡)으로 롤백되지 않고 ♥로 유지되는 현상 확인
* **관찰되는 증상**: 서버 저장이 실패했음에도 사용자 화면에는 즐겨찾기가 유지되어 서버와 클라이언트 간 불일치 발생
* **정상 동작**: API 실패 시 즉시 이전 즐겨찾기 상태로 UI가 롤백되어야 함
* **오류 발생 원인**: `toggleFavorite`의 에러 catch 블록에서 optimistic update를 롤백하는 로직이 누락됨
* **PPO가 탐색해야 할 행동**: 즐겨찾기 클릭 -> HTTP 실패 응답 확인 -> UI 롤백 여부 확인

  4. 1행 헤더의 `시작시간`, `종료시간`, `인원`, `상태` 컬럼과 실제 2행 이하 데이터 로우 값 비교
* **관찰되는 증상**: 헤더의 `시작시간` 위치에 종료시간이, `인원` 위치에 상태 문자열이 위치함
* **정상 동작**: CSV 헤더와 데이터 컬럼이 1:1로 일치해야 함
* **오류 발생 원인**: CSV 생성 백엔드 매핑 시 컬럼 인덱스 순서 오지정
* **PPO가 탐색해야 할 행동**: CSV 파일 다운로드 -> 헤더 컬럼 배열과 데이터 로우 배열 간 필드 타입 및 순서 불일치 검증

### SEC-440
* **SEC ID**: SEC-440
* **오류 유형**: 체크박스 그룹에서 전체 선택을 해제한 뒤 개별 항목 상태가 잘못 복구되는 문제
* **재현 조건**: 공간 찾기 화면의 시설 체크박스 필터에서 "전체 선택" 후 "전체 해제"를 클릭하여 검색할 때
* **재현 절차**:
  1. 공간 찾기 페이지(`/rooms`)로 이동
  2. 시설 필터 섹션에서 "전체 선택" 버튼 클릭 (모든 시설 체크)
  3. "전체 해제" 버튼 클릭 (모든 체크박스 체크 해제됨)
  4. 공간 검색 실행
  5. 결과 목록 또는 전송된 API 쿼리 파라미터에 '화상회의' 시설 필터가 잔존해 있는지 확인
* **관찰되는 증상**: 체크박스 UI는 모두 꺼져 있지만 실제 검색 결과는 '화상회의' 시설을 가진 룸으로 한정되어 검색됨
* **정상 동작**: 전체 해제 시 모든 필터가 해제되어 전체 공간이 노출되어야 함
* **오류 발생 원인**: 전체 해제 시 화면의 체크 상태만 해제하고 내부 쿼리 state에서 특정 항목이 제거되지 않음
* **PPO가 탐색해야 할 행동**: 전체 선택 -> 전체 해제 -> 검색 -> UI 상태와 실제 반환 목록/파라미터 불일치 탐색
