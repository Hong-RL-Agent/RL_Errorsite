## 📋 정상 기능 요약

- **보험 청구 접수 및 심사 관제 대장**: 45건의 보험 청구, 서류검토, 심사중, 보완요청, 지급승인, 지급완료, 반려 관제.
- **가입자 명단 & 보험 상품 관제**: 35명 가입자 인적/계좌 정보 및 15개 보험 상품 약관 산정 비율 관리.
- **지급 내역 & 심사 메모 대장**: 30건의 지급 처리 내역, 70건의 손해사정 심사 메모 이력 관제.
- **활동 로그 & 책임자 권한 관리**: 80건의 손해사정 승인 활동 로그 및 수석 손해사정사(MANAGER)/사정원(STAFF) 권한 관리.

## ⚠️ 의도적으로 삽입된 8가지 복합 오류 목록

1. **Frontend + Backend 요청 순서 충돌**
   - **설명**: 청구 상태를 '지급승인'(PAYMENT_APPROVED)으로 변경(3초 지연 완료)한 직후 지급 금액을 수정(0.1초 완료)하면, 지급 금액 수정 API는 먼저 완료되나 3초 뒤 완료되는 상태 변경 API가 요청 시작 시점의 구 DB 스냅샷(이전 상태)을 덮어써 저장하여 새로고침 시 청구 목록의 상태와 지급 상세의 상태가 서로 달라집니다.

2. **Backend + JSON DB 상태 충돌**
   - **설명**: 청구 반려 API(0.5초 완료)를 호출한 직후 서류 보완 완료 API를 호출(4초 지연 완료)하면, 반려 요청은 성공하지만 늦게 완료된 보완 완료 요청이 반려된 청구를 다시 UNDER_REVIEW 심사중 상태로 복원시킵니다. 청구 목록에서는 반려, 서류 검토 탭에서는 심사중으로 표시됩니다.

3. **Frontend 정렬 인덱스 오류**
   - **설명**: 청구 목록을 청구금액순/접수일순으로 정렬한 뒤 상세 버튼을 누르면 UI 알림은 클릭한 청구 번호로 뜨지만, 백엔드 저장 데이터는 정렬 전 원본 배열의 다른 청구 ID에 연결되는 결함입니다.

4. **통계 집계 불일치**
   - **설명**: 지급 내역을 삭제(`DELETE /api/payouts/:id`) 처리하여 지급 내역 목록에서 소거하더라도, 월별 지급 총액(`claimStats.totalPayoutAmount`), 상품별 청구율, 대시보드 승인율 수치에는 차감되지 않고 계속 잔존합니다.

5. **Network stale response 오류**
   - **설명**: 보험 상품 필터('무배당 실손의료비보장보험' 3초 지연 ➔ '프리미엄 암진단비 종합보험' 0.2초 완료)와 청구 상태 필터를 빠르게 변경 시 오래된 응답(실손의료비)이 최신 청구 목록을 덮어써 청구 목록은 오래된 필터 결과, 오른쪽 지급 요약은 최신 필터 기준 수치로 서로 불일치합니다.

6. **Session + Cache 잔존 오류**
   - **설명**: 심사자 A가 청구 상세를 본 뒤 심사자 B로 로그인하면 청구 목록은 B 담당 기준으로 바뀌지만, 상단 심사 대기 건수 및 최근 청구 요약 캐시(`cachedPendingAudits`, `cachedRecentClaim`)는 A 데이터가 남아 노출됩니다.

7. **Backend 권한 로그 오류**
   - **설명**: 권한 없는 직원(role !== 'MANAGER')이 지급 승인 API(`POST /api/claims/:id/approve-unauthorized`)를 호출하면 HTTP 403을 반환하지만, 서버 내부 활동 로그에는 '지급 승인 성공 (PAYOUT APPROVAL COMPLETED SUCCESSFULLY - 200 OK)'으로 잘못 기록됩니다.

8. **부분 저장 오류**
   - **설명**: 가입자 정보 수정 모달/패널에서 주소, 연락처, 계좌번호를 동시에 수정하면 백엔드 data.json에는 주소와 계좌번호만 저장되고 연락처는 이전 값을 유지하지만, 프론트엔드는 세 항목 모두 수정 성공한 것으로 표시합니다.

## 🧪 테스트 시나리오

1. **Error 1 테스트**: 우측 관제 패널에서 청구 상태 변경 선택 후 `상태 변경 후 즉시 지급금액 수정 (Error 1)` 클릭 ➔ 0.1초 후 지급금액 수정 응답 ➔ 3초 후 상태 변경 응답 완료 ➔ 새로고침 시 이전 상태로 롤백 저장됨을 확인.
2. **Error 2 테스트**: 우측 관제 패널에서 `⚡ 청구 반려 처리 후 서류 보완 연쇄 등록 (Error 2)` 클릭 ➔ 0.5초 후 청구 반려 응답 ➔ 4초 후 서류 보완 응답 완료 ➔ 반려된 청구가 UNDER_REVIEW 심사중 상태로 복원됨을 확인.
3. **Error 3 테스트**: 좌측 사이드바에서 `청구 금액 높은순` 정렬 선택 ➔ 최상단 청구의 `상세` 클릭 ➔ UI 상단 청구ID와 우측 관제 패널의 가입자/지급금액 정보가 상이함을 확인.
4. **Error 4 테스트**: 중앙 지급 내역 대장에서 `🗑️ 지급 내역 삭제` 클릭 ➔ 대장에서는 삭제되나 월별 지급 총액 수치가 유지됨을 확인.
5. **Error 5 테스트**: 좌측 보험 상품 필터를 `무배당 실손의료비보장보험` 선택 직후 `프리미엄 암진단비 종합보험` 선택 ➔ 3초 후 늦은 이전 실손의료비 결과가 최신 암진단비 청구 목록을 덮어씀을 확인.
6. **Error 6 테스트**: 상단 로그인 심사자를 `김심사 수석`에서 `이검토 선임`으로 전환 ➔ 청구 목록은 B로 바뀌나 상단 KPI 심사 대기 건수는 A 데이터로 잔존함을 확인.
7. **Error 7 테스트**: 상단 계정을 일반 사정원으로 테스트 시 `🔒 권한 없는 직원의 지급 승인 시도` 클릭 ➔ UI/API는 HTTP 403 오류 반환 ➔ 백엔드 콘솔 로그에는 SUCCESS (200 OK)로 잘못 작성됨을 확인.
8. **Error 8 테스트**: 우측 하단 가입자 정보 수정 패널에서 연락처 포함 입력 후 `가입자 정보 저장` 클릭 ➔ 토스트는 성공으로 표시되나 새로고침 시 연락처만 수정되지 않았음을 확인.
