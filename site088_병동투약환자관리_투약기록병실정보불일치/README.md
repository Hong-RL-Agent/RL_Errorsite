## 📋 정상 기능 요약

- **병동 병실 배치도 & 환자 현황**: 20개 이상의 3A, 3B, 4A, 4B, 5A, ICU 병실 재실 인원 및 배치 모니터링.
- **입원 환자 관리**: 30명 이상의 병동 입원 환자 진단명, 중증도, 입원 상태(입원중/퇴원) 조회.
- **통합 투약 일정표 & 기록**: 70개 이상의 의약품 처방 용량, 투약 예정 시간, 투약 상태(예정/완료/지연) 관리.
- **병실 이동 & 메모 관리**: 병실 이동 모달 변경 및 환자 주의사항, 보호자 연락처, 간호 메모 관리.

## ⚠️ 의도적으로 삽입된 8가지 복합 오류 목록

1. **Frontend + Backend 요청 순서 충돌**
   - **설명**: 환자의 병실을 이동(3초 지연 완료)한 직후 투약 상태를 완료로 변경(0.1초 완료)하면, 투약 상태 변경 API는 먼저 성공하지만 3초 뒤 완료되는 병실 이동 API 내부에 이전 병실 정보(`roomNo`)가 동봉 저장되어 새로고침 시 환자 상세의 병실과 투약 기록의 병실이 서로 달라집니다.

2. **Backend + JSON DB 상태 충돌**
   - **설명**: 퇴원 처리 API(0.5초 완료)를 호출한 직후 투약 기록 등록 API를 호출(4초 지연 완료)하면, 퇴원 처리는 먼저 성공하지만 늦게 완료된 투약 등록 요청이 퇴원 환자를 다시 'ADMITTED'(입원중) 상태로 재활성화시킵니다. 환자 목록에서는 퇴원으로 보이고, 투약 일정표에서는 입원중 환자처럼 표시됩니다.

3. **Frontend 정렬 인덱스 오류**
   - **설명**: 환자 목록을 중증도순으로 정렬한 뒤 상세 버튼을 누르면 UI 상단 이름은 클릭한 환자명으로 표시되나 상세 패널의 병실과 투약 내역은 원본 정렬 전 배열의 다른 환자 데이터가 노출됩니다.

4. **통계 집계 불일치**
   - **설명**: 투약 기록을 삭제(`DELETE /api/medications/:id`) 처리하여 이력 대장에서 소거하더라도, 병동별 투약 완료율(`medicationCompletionRate`), 누락 건수, 간호사별 처리량 그래프 수치에는 차감되지 않고 계속 유지됩니다.

5. **Network stale response 오류**
   - **설명**: 병동 필터('3A' 3초 지연 ➔ '3B' 0.2초 완료)와 투약 상태 필터를 빠르게 변경 시 오래된 응답이 최신 목록을 덮어써 중앙 환자 목록은 오래된 필터 결과, 오른쪽 투약 요약 패널은 최신 필터 기준 데이터로 서로 불일치합니다.

6. **Session + Cache 잔존 오류**
   - **설명**: 간호사 A가 담당 환자 목록을 본 뒤 간호사 B로 로그인하면 환자 목록은 B 담당 기준으로 바뀌지만, 상단 투약 예정 개수 및 최근 환자 요약 캐시(`cachedScheduledCount`, `cachedRecentPatientSummary`)는 A 데이터가 남아 노출됩니다.

7. **Backend 권한 로그 오류**
   - **설명**: 권한 없는 간호사(role !== 'ADMIN')가 병실 이동 API(`PATCH /api/patients/:id/room`)를 호출하면 HTTP 403을 반환하지만, 서버 내부 활동 로그에는 '병실 이동 성공 (PATIENT ROOM MOVE SUCCESS - 200 OK)'으로 잘못 기록됩니다.

8. **부분 저장 오류**
   - **설명**: 환자 메모 수정 모달/패널에서 주의사항, 보호자 연락처, 간호 메모를 동시에 수정하면 백엔드 data.json에는 주의사항과 간호 메모만 저장되고 보호자 연락처는 이전 값을 유지하지만, 프론트엔드는 세 항목 모두 수정 성공한 것처럼 표시합니다.

## 🧪 테스트 시나리오

1. **Error 1 테스트**: 우측 패널에서 `병실 이동 & 투약완료` 클릭 ➔ 0.1초 후 투약 완료 응답 ➔ 3초 후 병실 이동 응답이 완료되며 새로고침 시 환자 상세 병실과 투약 기록 병실 간 불일치 확인.
2. **Error 2 테스트**: 우측 패널에서 `⚡ 환자 퇴원 후 처방 투약 추가` 클릭 ➔ 0.5초 후 퇴원 응답 ➔ 4초 후 투약 등록 응답이 완료되며 환자 목록(퇴원)과 투약 일정표(입원중) 간 상태 불일치 확인.
3. **Error 3 테스트**: 좌측 사이드바에서 `중증도 높은순` 정렬 선택 ➔ 상단 환자건의 상세보기 클릭 ➔ UI 상단 환자명과 상세 패널의 병실/투약 내역이 상이함을 확인.
4. **Error 4 테스트**: 중앙 투약 대장에서 `🗑️ 삭제` 클릭 ➔ 대장에서는 삭제되나 병동 투약 완료율 및 간호사 처리량 그래프 수치가 유지됨을 확인.
5. **Error 5 테스트**: 좌측 병동 필터를 `3A 병동` 선택 직후 `3B 병동` 선택 ➔ 3초 후 늦은 이전 결과가 최신 목록을 덮어씀을 확인.
6. **Error 6 테스트**: 상단 로그인 사용자를 `김간호 수간호사`에서 `이간호 주임`으로 전환 ➔ 환자 목록은 B로 바뀌나 상단 KPI 투약 예정 개수는 A 데이터로 잔존함을 확인.
7. **Error 7 테스트**: 상단 계정을 `이간호 주임 (일반 간호사)`으로 전환 후 `🔒 일반 간호사의 병실 이동 시도` 클릭 ➔ UI/API는 HTTP 403 오류 반환 ➔ 백엔드 콘솔 로그에는 SUCCESS (200 OK)로 잘못 작성됨을 확인.
8. **Error 8 테스트**: 우측 하단 메모 수정 패널에서 보호자 연락처 포함 입력 후 `메모 수정 저장` 클릭 ➔ 토스트는 성공으로 표시되나 새로고침 시 보호자 연락처만 수정되지 않았음을 확인.
