## 📋 정상 기능 요약

- **층별 객실 배치도 (45개 객실)**: 1층~3층 전체 객실 상태(체크인, 체크아웃, 청소중, 청소완료, 점검필요, 예약중) 시각적 모니터링.
- **하우스키핑 청소 수행 대장 (50건)**: 직원별 객실 청소/점검/살균 이력 대장 관리 및 이력 소거 기능.
- **실시간 고객 요청 접수 대장 (25건)**: 객실별 타월, 추가 어메니티, 아기침대 등 서비스 요청 모니터링.
- **객실 및 하우스키핑 배정 제어**: 하우스키핑 담당자 변경, 객실 상태 변경, 체크아웃 및 청소 완료 승인.

## ⚠️ 의도적으로 삽입된 8가지 복합 오류 목록

1. **Frontend + Backend 요청 순서 충돌**
   - **설명**: 객실 상태를 'CLEANING'(청소중)으로 변경(3초 지연 완료)한 직후 하우스키핑 직원을 변경(0.1초 완료)하면, 직원 변경 API는 먼저 성공하지만 3초 뒤 완료되는 상태 변경 API 내부에 요청 시점의 구 스냅샷(이전 직원)이 동봉 저장되어 새로고침 시 객실 카드의 담당 직원과 청소 작업 상세의 담당 직원이 서로 달라집니다.

2. **Backend + JSON DB 상태 충돌**
   - **설명**: 체크아웃 처리 API(0.5초 완료)를 호출한 직후 청소 완료 API를 호출(4초 지연 완료)하면, 체크아웃 처리는 먼저 성공하지만 늦게 완료된 청소 완료 요청이 객실을 'CHECKED_IN'(체크인) 상태로 다시 바꿔버립니다. 객실 배치도에서는 체크아웃, 하우스키핑 보드에서는 체크인으로 표시됩니다.

3. **Frontend 정렬 인덱스 오류**
   - **설명**: 객실 목록을 가격순/고층순으로 정렬한 뒤 상세보기 버튼을 누르면 화면 상단 객실 번호는 클릭한 객실로 표시되나 우측 관제 패널의 예약자 및 청소 상태는 원본 정렬 전 배열의 다른 객실 기준 데이터가 노출됩니다.

4. **통계 집계 불일치**
   - **설명**: 청소 완료 로그를 삭제(`DELETE /api/cleaning-logs/:id`) 처리하여 이력 대장에서 소거하더라도, 직원별 완료 건수, 객실 청소율(`hotelStats.cleaningCompletionRate`), 대시보드 통계 수치에는 차감되지 않고 계속 유지됩니다.

5. **Network stale response 오류**
   - **설명**: 층 필터('1층' 3초 지연 ➔ '2층' 0.2초 완료)와 객실 상태를 빠르게 변경 시 오래된 응답이 최신 목록을 덮어써 객실 배치도는 오래된 필터 결과, 오른쪽 객실 요약은 최신 필터 기준 수치로 서로 불일치합니다.

6. **Session + Cache 잔존 오류**
   - **설명**: 관리자 A가 고객 요청 상세를 본 뒤 관리자 B로 로그인하면 객실 목록은 B 기준으로 바뀌지만, 미처리 고객 요청 개수 및 최근 객실 상세 요약 캐시(`cachedRequestCount`, `cachedRecentRoomSummary`)는 A 데이터가 남아 노출됩니다.

7. **Backend 권한 로그 오류**
   - **설명**: 권한 없는 직원(role !== 'ADMIN')이 객실 점검 완료 API(`POST /api/rooms/:id/inspect`)를 호출하면 HTTP 403을 반환하지만, 서버 내부 활동 로그에는 '객실 점검 완료 성공 (ROOM INSPECTION COMPLETED SUCCESSFULLY - 200 OK)'으로 잘못 기록됩니다.

8. **부분 저장 오류**
   - **설명**: 객실 정보 수정 모달/패널에서 객실 타입, 숙박 가격, 청소 메모를 동시에 수정하면 백엔드 data.json에는 객실 타입과 청소 메모만 저장되고 숙박 가격은 이전 값을 유지하지만, 프론트엔드는 세 항목 모두 수정 성공한 것처럼 표시합니다.

## 🧪 테스트 시나리오

1. **Error 1 테스트**: 우측 관제 패널에서 객실 상태 `CLEANING (청소중)` 선택 ➔ `상태 변경 (Error 1)` 클릭 ➔ 0.1초 후 담당 직원 변경 응답 ➔ 3초 후 상태 변경 응답 완료 ➔ 새로고침 시 담당 직원이 이전 직원으로 롤백됨을 확인.
2. **Error 2 테스트**: 우측 관제 패널에서 `⚡ 체크아웃 처리 후 청소 완료 승인` 클릭 ➔ 0.5초 후 체크아웃 응답 ➔ 4초 후 청소 완료 응답 완료 ➔ 객실이 체크아웃에서 다시 CHECKED_IN (체크인) 상태로 재활성화됨을 확인.
3. **Error 3 테스트**: 좌측 사이드바에서 `가격 높은순` 정렬 선택 ➔ 최상단 객실의 상세보기 클릭 ➔ UI 상단 객실 번호와 우측 관제 패널의 예약자/청소상태 정보가 상이함을 확인.
4. **Error 4 테스트**: 중앙 하우스키핑 청소 수행 대장에서 `🗑️ 로그 삭제` 클릭 ➔ 대장에서는 삭제되나 대시보드 청소율 및 직원별 완료 수치가 유지됨을 확인.
5. **Error 5 테스트**: 좌측 층 필터를 `1층 객실` 선택 직후 `2층 객실` 선택 ➔ 3초 후 늦은 이전 1층 결과가 최신 2층 객실 배치도를 덮어씀을 확인.
6. **Error 6 테스트**: 상단 로그인 관리자를 `김지배인 (총지배인)`에서 `이하우스 (하우스키핑 매니저)`로 전환 ➔ 객실 목록은 B로 바뀌나 상단 KPI 미처리 고객 요청 개수는 A 데이터로 잔존함을 확인.
7. **Error 7 테스트**: 상단 계정을 `박스태프 (일반 사원)`로 전환 후 `🔒 일반 사원의 강제 객실 점검 완료 시도` 클릭 ➔ UI/API는 HTTP 403 오류 반환 ➔ 백엔드 콘솔 로그에는 SUCCESS (200 OK)로 잘못 작성됨을 확인.
8. **Error 8 테스트**: 우측 하단 객실 정보 수정 패널에서 숙박 가격 포함 입력 후 `객실 정보 저장` 클릭 ➔ 토스트는 성공으로 표시되나 새로고침 시 숙박 가격만 수정되지 않았음을 확인.
