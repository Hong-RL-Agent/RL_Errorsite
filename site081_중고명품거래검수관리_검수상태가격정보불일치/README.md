1. **백엔드 실행**:
   ```bash
   cd backend
   npm install
   npm start
   ```

2. **프론트엔드 실행**:
   ```bash
   cd frontend
   npm install
   npm run dev
   ```

## 📋 정상 기능 요약

- **상품 탐색 및 거래 카탈로그**: 20개 이상의 샤넬, 에르메스, 롤렉스, 루이비통 명품 항목 조회 및 정품 검수 상태 확인.
- **전문 검수 대장**: 25개 이상의 감정위원 판정 소견, 정품 등급(S급, A+급) 및 검수 이력 점검.
- **거래 체결 및 정산 대장**: 18개 이상의 거래 내역 대장 조회, 셀러별 체결액 산정 및 취소 관리.
- **판매자 대시보드 및 세션 스위칭**: 10명 이상의 셀러 프로필 관리 및 SLR-01/SLR-02 로그인 스위칭.

## ⚠️ 의도적으로 삽입된 복합 오류 목록

1. **Frontend + Backend 요청 순서 충돌**
   - **설명**: 판매 가격을 수정한 직후(3초 지연 완료) 검수 상태를 변경(0.1초 완료)하면, 검수 상태 변경 API는 먼저 성공하지만 3초 뒤 완료되는 가격 수정 API 내부에 이전 검수 상태(`inspectionStatus`)가 동봉 저장되어 새로고침 시 새 가격과 이전 검수 상태 조합이 저장됩니다.

2. **Backend + JSON DB 상태 충돌**
   - **설명**: 검수 반려(0.5초 완료) 직후 판매자가 상품 설명을 수정(4초 지연 완료)하면, 반려 요청은 먼저 0.5초 만에 성공하지만 늦게 도착한 설명 수정 요청이 반려된 상품을 다시 'INSPECTING'(검수 대기) 상태로 재활성화시킵니다. 목록에서는 반려, 상세에서는 검수 대기로 불일치하게 됩니다.

3. **Frontend 정렬 인덱스 오류**
   - **설명**: 상품 목록을 가격순으로 정렬한 뒤 구매 신청 버튼을 누르면 UI 알림은 클릭한 상품명으로 표시되나 backend 저장 거래 데이터는 원본 배열의 다른 index 상품 id로 저장됩니다.

4. **통계 데이터 불일치**
   - **설명**: 거래 내역을 삭제(`DELETE /api/transactions/:id`) 처리하여 대장에서 소거하더라도, 판매자 누적 판매액(`totalSales`)과 브랜드별 거래 통계 그래프에는 차감되지 않고 계속 유지됩니다.

5. **Network stale response 오류**
   - **설명**: 브랜드 필터('CHANEL' 3초 지연 ➔ 'HERMES' 0.2초 완료)와 검수 상태 필터를 빠르게 변경 시 오래된 응답이 최신 목록을 덮어써 중앙 상품 목록은 오래된 필터 결과, 오른쪽 검수 요약은 최신 필터 기준 데이터로 서로 불일치합니다.

6. **Session + Cache 잔존 오류**
   - **설명**: 판매자 A의 상품 관리 화면을 본 뒤 판매자 B로 로그인하면 상품 목록은 B 기준으로 바뀌지만, 판매 예정 금액과 검수 대기 알림 캐시(`cachedSalesAmount`, `cachedInspectionNotice`)는 A 데이터가 남아 노출됩니다.

7. **Server 파일 경로 오류**
   - **설명**: 상품 이미지 파일 이름에 한글과 공백이 포함된 경우(`샤넬 가방 (특S급).jpg`), 목록 이미지에는 정상 표시되나 상세 갤러리 API 응답 시 이중 URL 인코딩을 적용해 상세 갤러리 탭에서만 이미지가 404로 깨집니다.

## 🧪 테스트 시나리오

1. **Error 1 테스트**: 우측 패널에서 상품 가격 입력 후 `가격 수정` 클릭 직후 검수 상태 변경 ➔ 3초 후 새로고침 시 가격은 바뀌었으나 검수 상태는 이전 값으로 롤백됨을 확인.
2. **Error 2 테스트**: 우측 패널에서 `⚡ 검수 반려 후 설명 수정` 클릭 ➔ 0.5초 후 반려 응답 ➔ 4초 후 설명 수정 응답이 완료되며 목록(반려)과 상세 인스펙터(검수 대기) 간 상태 불일치 확인.
3. **Error 3 테스트**: 좌측 사이드바에서 `높은 가격순` 정렬 선택 ➔ 상단 상품의 구매 신청 클릭 ➔ UI 알림과 실제 backend DB 저장 상품 id가 상이함을 확인.
4. **Error 4 테스트**: 중앙 거래 내역 대장에서 `🗑️ 취소` 클릭 ➔ 대장에서는 삭제되나 셀러 누적 판매액 및 브랜드 통계 그래프 수치가 유지됨을 확인.
5. **Error 5 테스트**: 좌측 브랜드 필터를 `샤넬` 선택 직후 `에르메스` 선택 ➔ 3초 후 늦은 이전 결과가 최신 목록을 덮어씀을 확인.
6. **Error 6 테스트**: 상단 로그인 셀러를 `셀러 A`에서 `셀러 B`로 전환 ➔ 상품 목록은 B로 바뀌나 상단 KPI 판매 예정 금액은 A 데이터로 잔존함을 확인.
7. **Error 7 테스트**: 상품 목록에서 `에르메스 버킨 30 엡솜 에토프` 선택 ➔ 우측 상세 갤러리 미리보기 패널에서 이미지만 404로 깨짐을 확인.
