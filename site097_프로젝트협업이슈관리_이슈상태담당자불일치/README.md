## 📋 정상 기능 요약

- **애자일 이슈 칸반보드**: TODO, IN_PROGRESS, REVIEW, DONE, HOLD 5단계 카드 컬럼 모니터링.
- **프로젝트 및 팀원 대장**: 8개 프로젝트 및 20명의 팀원별 배정 이슈 및 진척도 관제.
- **통합 이슈 테이블 및 댓글**: 45개 이슈의 상세 파이프라인, 우선순위, 마감일 및 70건의 댓글 관리.
- **작업 이력 & 감사 로그**: 80건의 팀원별 이슈 상태 변경, 담당자 수정 활동 감사 로그 제공.

## ⚠️ 의도적으로 삽입된 8가지 복합 오류 목록

1. **Frontend + Backend 요청 순서 충돌**
   - **설명**: 이슈 상태를 '진행 중'(IN_PROGRESS)으로 변경(3초 지연 완료)한 직후 담당자를 변경(0.1초 완료)하면, 담당자 변경 API는 먼저 완료되나 3초 뒤 완료되는 상태 변경 API가 요청 시작 시점의 구 DB 스냅샷(이전 담당자)을 덮어써 저장하여 새로고침 시 칸반보드의 담당자와 이슈 상세의 담당자가 서로 달라집니다.

2. **Backend + JSON DB 상태 충돌**
   - **설명**: 이슈 삭제 API(0.5초 완료)를 호출한 직후 댓글 작성 API를 호출(4초 지연 완료)하면, 이슈 삭제는 성공하지만 늦게 완료된 댓글 작성 요청이 삭제된 이슈를 다시 IN_PROGRESS 상태로 DB에 복원시킵니다. 이슈 목록에서는 삭제됨, 활동 로그에서는 댓글이 달린 진행 중 이슈로 표시됩니다.

3. **Frontend 정렬 인덱스 오류**
   - **설명**: 이슈 목록을 우선순위순/마감일순으로 정렬한 뒤 상세 버튼을 누르면 상단 제목은 클릭한 이슈 제목으로 뜨지만, 상세 패널의 담당자와 댓글은 원본 정렬 전 배열의 다른 이슈 데이터가 표시됩니다.

4. **통계 집계 불일치**
   - **설명**: 완료 이슈 로그를 삭제(`DELETE /api/logs/:id`) 처리하여 로그 목록에서 소거하더라도, 프로젝트 완료율(`projectStats.averageCompletionRate`), 담당자별 완료 건수, 대시보드 번다운 차트 수치에는 차감되지 않고 계속 잔존합니다.

5. **Network stale response 오류**
   - **설명**: 프로젝트 필터('PRJ-101' 3초 지연 ➔ 'PRJ-102' 0.2초 완료)와 상태 필터를 빠르게 변경 시 오래된 응답(PRJ-101)이 최신 이슈 목록을 덮어써 이슈 목록은 오래된 필터 결과, 오른쪽 프로젝트 요약은 최신 필터 기준 수치로 서로 불일치합니다.

6. **Session + Cache 잔존 오류**
   - **설명**: 사용자 A가 담당 이슈 목록을 본 뒤 사용자 B로 로그인하면 이슈 목록은 B 담당 기준으로 바뀌지만, 상단 내 이슈 개수 및 최근 이슈 상세 요약 캐시(`cachedMyIssueCount`, `cachedRecentIssue`)는 A 데이터가 남아 노출됩니다.

7. **Backend 권한 로그 오류**
   - **설명**: 권한 없는 일반 팀원(role !== 'ADMIN')이 프로젝트 삭제 API(`DELETE /api/projects/:id`)를 호출하면 HTTP 403을 반환하지만, 서버 내부 활동 로그에는 '프로젝트 삭제 성공 (PROJECT DELETED SUCCESSFULLY - 200 OK)'으로 잘못 기록됩니다.

8. **부분 저장 오류**
   - **설명**: 이슈 수정 모달/패널에서 제목, 마감일, 우선순위를 동시에 수정하면 백엔드 data.json에는 제목과 우선순위만 저장되고 마감일은 이전 값을 유지하지만, 프론트엔드는 세 항목 모두 수정 성공한 것으로 표시합니다.

## 🧪 테스트 시나리오

1. **Error 1 테스트**: 우측 관제 패널에서 상태 변경 선택 후 `상태 변경 후 즉시 담당자 변경 (Error 1)` 클릭 ➔ 0.1초 후 담당자 변경 응답 ➔ 3초 후 상태 변경 응답 완료 ➔ 새로고침 시 이전 담당자로 롤백 저장됨을 확인.
2. **Error 2 테스트**: 우측 관제 패널에서 `⚡ 이슈 삭제 후 댓글 작성 연쇄 호출 (Error 2)` 클릭 ➔ 0.5초 후 이슈 삭제 응답 ➔ 4초 후 댓글 작성 응답 완료 ➔ 삭제된 이슈가 IN_PROGRESS 상태로 DB에 복원됨을 확인.
3. **Error 3 테스트**: 좌측 사이드바에서 `우선순위 높은순` 정렬 선택 ➔ 최상단 이슈의 `상세` 클릭 ➔ UI 상단 제목과 우측 관제 패널의 담당자/댓글 정보가 상이함을 확인.
4. **Error 4 테스트**: 중앙 작업 로그 대장에서 `🗑️ 로그 삭제` 클릭 ➔ 대장에서는 삭제되나 프로젝트 완료율 및 번다운 차트 수치가 유지됨을 확인.
5. **Error 5 테스트**: 좌측 프로젝트 필터를 `PRJ-101` 선택 직후 `PRJ-102` 선택 ➔ 3초 후 늦은 이전 PRJ-101 결과가 최신 PRJ-102 이슈 목록을 덮어씀을 확인.
6. **Error 6 테스트**: 상단 로그인 작업자를 `김프로젝트 (PM 총괄)`에서 `이아키텍트 (수석)`로 전환 ➔ 이슈 목록은 B로 바뀌나 상단 KPI 내 배정 이슈 건수는 A 데이터로 잔존함을 확인.
7. **Error 7 테스트**: 상단 계정을 일반 팀원으로 테스트 시 `🔒 일반 팀원의 프로젝트 강제 삭제 시도` 클릭 ➔ UI/API는 HTTP 403 오류 반환 ➔ 백엔드 콘솔 로그에는 SUCCESS (200 OK)로 잘못 작성됨을 확인.
8. **Error 8 테스트**: 우측 하단 이슈 정보 수정 패널에서 마감일 포함 입력 후 `이슈 정보 저장` 클릭 ➔ 토스트는 성공으로 표시되나 새로고침 시 마감일만 수정되지 않았음을 확인.
