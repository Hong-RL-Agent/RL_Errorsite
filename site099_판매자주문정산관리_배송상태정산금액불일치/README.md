## 📋 정상 기능 요약

- **판매자 스토어 주문 대장**: 45건의 주문 결제완료, 상품준비, 배송중, 배송완료, 구매확정 상태 관제.
- **판매 정산 및 매출 대장**: 30건의 주문별 정산 예정/완료 금액, 수수료 5% 계산 및 35개 등록 상품 관리.
- **구매자 & 배송 처리 로그**: 30명의 구매자 인적사항 및 60건의 택배사 송장 등록, 집화 물류 로그 제공.
- **판매자 계정 및 수수료 관리**: 5개 판매자 스토어별 파워스토어/빅파워 등급 및 정산 현황 모니터링.

## ⚠️ 의도적으로 삽입된 8가지 복합 오류 목록

1. **Frontend + Backend 요청 순서 충돌**
   - **설명**: 주문 배송 상태를 '배송중'(SHIPPING)으로 변경(3초 지연 완료)한 직후 정산 금액을 수정(0.1초 완료)하면, 정산 금액 수정 API는 먼저 완료되나 3초 뒤 완료되는 배송 상태 변경 API가 요청 시작 시점의 구 DB 스냅샷(이전 배송 상태)을 덮어써 저장하여 새로고침 시 주문 상세 상태와 정산 상세 상태가 서로 달라집니다.

2. **Backend + JSON DB 상태 충돌**
   - **설명**: 주문 취소 API(0.5초 완료)를 호출한 직후 송장 등록 API를 호출(4초 지연 완료)하면, 주문 취소는 성공하지만 늦게 완료된 송장 등록 요청이 취소된 주문을 다시 SHIPPING 배송중 상태로 복원시킵니다. 주문 목록에서는 취소됨, 배송 로그에서는 배송중으로 표시됩니다.

3. **Frontend 정렬 인덱스 오류**
   - **설명**: 주문 목록을 결제금액순/주문일순으로 정렬한 뒤 상세 보기 버튼을 누르면 상단 주문번호는 클릭한 주문번호로 뜨지만, 오른쪽 상세 패널의 구매자와 상품은 원본 정렬 전 배열의 다른 주문 데이터가 표시됩니다.

4. **통계 집계 불일치**
   - **설명**: 정산 데이터를 삭제(`DELETE /api/settlements/:id`) 처리하여 정산 목록에서 소거하더라도, 월별 정산 예정 금액(`sellerStats.expectedSettlement`), 상품별 매출, 판매자 대시보드 통계 수치에는 차감되지 않고 계속 잔존합니다.

5. **Network stale response 오류**
   - **설명**: 주문 상태 필터('결제완료' 3초 지연 ➔ '상품준비' 0.2초 완료)와 카테고리 필터를 빠르게 변경 시 오래된 응답(결제완료)이 최신 주문 목록을 덮어써 주문 목록은 오래된 필터 결과, 오른쪽 정산 요약은 최신 필터 기준 수치로 서로 불일치합니다.

6. **Session + Cache 잔존 오류**
   - **설명**: 판매자 A가 주문 상세를 본 뒤 판매자 B로 로그인하면 주문 목록은 B 스토어 기준으로 바뀌지만, 상단 오늘 신규 주문 수 및 정산 예정 금액 캐시(`cachedTodayOrders`, `cachedSettlementAmount`)는 A 데이터가 남아 노출됩니다.

7. **Backend 권한 로그 오류**
   - **설명**: 권한 없는 판매자(sellerId 미일치)가 다른 판매자의 주문 취소 API(`POST /api/orders/:id/cancel-unauthorized`)를 호출하면 HTTP 403을 반환하지만, 서버 내부 활동 로그에는 '주문 취소 성공 (ORDER CANCELLED SUCCESSFULLY - 200 OK)'으로 잘못 기록됩니다.

8. **부분 저장 오류**
   - **설명**: 상품 정보 수정 모달/패널에서 상품명, 판매가, 배송비를 동시에 수정하면 백엔드 data.json에는 상품명과 배송비만 저장되고 판매가는 이전 값을 유지하지만, 프론트엔드는 세 항목 모두 수정 성공한 것으로 표시합니다.

## 🧪 테스트 시나리오

1. **Error 1 테스트**: 우측 관제 패널에서 배송 상태 변경 선택 후 `상태 변경 후 즉시 정산액 수정 (Error 1)` 클릭 ➔ 0.1초 후 정산액 수정 응답 ➔ 3초 후 배송 상태 변경 응답 완료 ➔ 새로고침 시 이전 배송 상태로 롤백 저장됨을 확인.
2. **Error 2 테스트**: 우측 관제 패널에서 `⚡ 주문 취소 후 송장 등록 연쇄 호출 (Error 2)` 클릭 ➔ 0.5초 후 주문 취소 응답 ➔ 4초 후 송장 등록 응답 완료 ➔ 취소된 주문이 SHIPPING 배송중 상태로 복원됨을 확인.
3. **Error 3 테스트**: 좌측 사이드바에서 `결제 금액 높은순` 정렬 선택 ➔ 최상단 주문의 `상세` 클릭 ➔ UI 상단 주문ID와 우측 관제 패널의 구매자/상품 정보가 상이함을 확인.
4. **Error 4 테스트**: 중앙 정산 대장에서 `🗑️ 정산 내역 삭제` 클릭 ➔ 대장에서는 삭제되나 정산 예정 금액 및 매출 수치가 유지됨을 확인.
5. **Error 5 테스트**: 좌측 주문 상태 필터를 `결제완료` 선택 직후 `상품준비` 선택 ➔ 3초 후 늦은 이전 결제완료 결과가 최신 상품준비 주문 목록을 덮어씀을 확인.
6. **Error 6 테스트**: 상단 로그인 판매자를 `스마트디지털 (판매자 A)`에서 `홈리빙 갤러리 (판매자 B)`로 전환 ➔ 주문 목록은 B로 바뀌나 상단 KPI 오늘 신규 주문 건수는 A 데이터로 잔존함을 확인.
7. **Error 7 테스트**: 상단 계정을 다른 판매자로 테스트 시 `🔒 권한 없는 타 판매자 주문 취소 시도` 클릭 ➔ UI/API는 HTTP 403 오류 반환 ➔ 백엔드 콘솔 로그에는 SUCCESS (200 OK)로 잘못 작성됨을 확인.
8. **Error 8 테스트**: 우측 하단 상품 정보 수정 패널에서 판매가 포함 입력 후 `상품 정보 저장` 클릭 ➔ 토스트는 성공으로 표시되나 새로고침 시 판매가만 수정되지 않았음을 확인.
