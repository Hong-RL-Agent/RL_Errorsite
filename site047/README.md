# site047 - Blue Horizon Bank (PPO 훈련용 뱅킹 서비스)

## 개요
이 프로젝트는 PPO(Proximal Policy Optimization) 강화학습 에이전트가 백엔드 API의 로직 오류를 탐지하도록 훈련시키기 위한 고충실도 테스트 환경입니다. 실제 은행 및 핀테크 서비스와 유사한 UI를 제공하며, 의도적으로 4개의 백엔드 로직 오류를 포함하고 있습니다.

## 프로젝트 정보
- **사이트 ID**: site047
- **포트**: 9156 (Frontend & Backend 통합)
- **기술 스택**: React, Vite, Express, Lucide-React
- **주제**: 은행 계좌 이체 내역서 관리

## 실행 방법
```bash
cd site047
npm install
npm start
```
브라우저에서 `http://localhost:9156`으로 접속하십시오.

## 의도된 백엔드 오류 (4개)

1. **site047-bug01 (incorrect-running-balance)**
   - **유형**: 누적 잔액 계산 오류
   - **트리거**: 거래 내역 조회 (`GET /api/transactions`)
   - **설명**: 거래 내역 목록을 불러올 때, 이전 항목의 잔액을 참조하는 로직에 오차(5555원)를 강제로 주입하여 전체 잔액 흐름이 일관되지 않게 만듭니다.
   - **탐지 지표**: `data.data[i].balance` 값이 실제 입출금 합산과 다름.

2. **site047-bug02 (unstable-pagination-order)**
   - **유형**: 페이지네이션 정렬 불안정
   - **트리거**: 1페이지 요청 (`GET /api/transactions?page=1`)
   - **설명**: 동일한 페이지(1페이지)를 다시 요청하거나 새로고침할 때, 정렬 기준이 랜덤하게 적용되어 거래 순서가 계속 바뀝니다.
   - **탐지 지표**: 동일한 `page` 요청에서 반환되는 `id` 목록의 순서가 불일치함.

3. **site047-bug03 (filter-boundary-error)**
   - **유형**: 필터 경계값 오류
   - **트리거**: 금액 필터 적용 (`GET /api/transactions/filter?minAmount=10000`)
   - **설명**: 최소 금액 필터를 적용할 때, 서버에서 경계값 조건을 잘못 설정하여 설정한 최소 금액보다 낮은 항목(예: 9000원대)이 포함되어 반환됩니다.
   - **탐지 지표**: 반환된 데이터 중 `amount < minAmount`인 항목이 존재함.

4. **site047-bug04 (inconsistent-debit-credit-flag)**
   - **유형**: 입출금 구분 오류
   - **트리거**: 거래 목록 및 상세 조회 (`GET /api/transactions`)
   - **설명**: 특정 인덱스의 거래 데이터에서 `type` 필드(credit/debit)가 실제 거래 내용과 반대로 표시됩니다.
   - **탐지 지표**: UI 표시 유형과 실제 데이터 로직 간의 불일치 탐지.

## 주요 기능
- 실시간 자산 대시보드 (입금/지출/잔액)
- 자산 분석 리포트 및 도넛 차트
- 상세 거래 내역 테이블 (페이지네이션 적용)
- 금액 기준 필터링 및 검색
- 거래 명세서 상세 모달 뷰

## PPO 학습 목표
- **수치 일관성 검증**: 잔액 계산 로직의 오류 탐지
- **상태 안정성 탐지**: 페이지네이션의 비결정적 정렬 감지
- **비즈니스 로직 유효성**: 필터링 조건과 결과의 일치 여부 확인
- **데이터 분류 무결성**: 입출금 플래그의 정확성 판단
