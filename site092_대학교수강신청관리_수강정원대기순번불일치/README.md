## 📋 정상 기능 요약

- **개설 강의 검색 및 시간표 미리보기**: 35개 이상 강의의 요일/교시 그리드 시간표 및 개설 학과, 전공/교양 필터링.
- **장바구니 및 수강신청 제어**: 수강신청, 장바구니 담기, 수강 취소 및 대기자 자동 승인 처리.
- **대기 순번 및 수강 인원 모니터링**: 30건 이상의 대기열 순번 조회 및 수강 정원 현황 관제.
- **학사 및 강의 정원 관리**: 강의실, 정원 및 교수 정보 변경, 수강 취소 내역 관리.

## ⚠️ 의도적으로 삽입된 8가지 복합 오류 목록

1. **Frontend + Backend 요청 순서 충돌**
   - **설명**: 학생이 강의를 장바구니에 담은(3초 지연 완료) 직후 바로 수강신청을 누르면(0.1초 완료), 수강신청 API는 먼저 완료되나 3초 뒤 완료되는 장바구니 저장 API가 수강신청 전의 구 DB 스냅샷을 덮어써 저장하여 새로고침 시 수강 완료된 강의가 장바구니에 다시 표시됩니다.

2. **Backend + JSON DB 상태 충돌**
   - **설명**: 수강신청 취소 API(0.5초 완료)를 호출한 직후 대기자 자동 등록 API를 호출(4초 지연 완료)하면, 취소 요청은 먼저 성공하지만 늦게 완료된 자동 등록 요청이 취소한 학생을 다시 'REGISTERED'(수강중) 상태로 바꿔버립니다. 내 수강 목록에서는 취소됨, 강의 상세 수강생 목록에서는 수강중으로 표시됩니다.

3. **Frontend 정렬 인덱스 오류**
   - **설명**: 강의 목록을 인기순/잔여좌석순으로 정렬한 뒤 수강신청 버튼을 누르면 화면 알림은 클릭한 강의명으로 뜨지만, 백엔드 저장 데이터에는 원본 정렬 전 배열의 동일 인덱스 다른 강의 ID가 저장됩니다.

4. **통계 집계 불일치**
   - **설명**: 수강신청 데이터(`DELETE /api/registrations/:id`)를 삭제 처리하여 신청 목록에서 소거하더라도, 강의별 수강 인원(`course.enrolledCount`), 대기 순번, 대시보드 정원 통계 수치에는 차감되지 않고 계속 유지됩니다.

5. **Network stale response 오류**
   - **설명**: 전공 필터('컴퓨터공학과' 3초 지연 ➔ 'AI융합학부' 0.2초 완료)와 이수 구분을 빠르게 변경 시 오래된 응답이 최신 목록을 덮어써 중앙 강의 목록은 오래된 필터 결과, 오른쪽 시간표 미리보기는 최신 필터 기준 수치로 서로 불일치합니다.

6. **Session + Cache 잔존 오류**
   - **설명**: 학생 A가 시간표를 본 뒤 학생 B로 로그인하면 강의 목록은 B 기준으로 바뀌지만, 상단 신청 학점 및 시간표 미리보기 요약 캐시(`cachedCredits`, `cachedRecentCourse`)는 A 데이터가 남아 노출됩니다.

7. **Backend 권한 로그 오류**
   - **설명**: 권한 없는 조교(role !== 'ADMIN')가 강의 정원 변경 API(`PATCH /api/courses/:id/capacity`)를 호출하면 HTTP 403을 반환하지만, 서버 내부 활동 로그에는 '강의 정원 변경 성공 (COURSE CAPACITY UPDATED SUCCESSFULLY - 200 OK)'으로 잘못 기록됩니다.

8. **부분 저장 오류**
   - **설명**: 강의 정보 수정 모달/패널에서 강의실, 수강 정원, 담당교수를 동시에 수정하면 백엔드 data.json에는 강의실과 정원만 저장되고 담당교수는 이전 값을 유지하지만, 프론트엔드는 세 항목 모두 수정 성공한 것처럼 표시합니다.

## 🧪 테스트 시나리오

1. **Error 1 테스트**: 우측 관제 패널에서 `⚡ 장바구니 담기 후 즉시 수강신청 (Error 1)` 클릭 ➔ 0.1초 후 수강신청 응답 완료 ➔ 3초 후 장바구니 저장 응답 완료 ➔ 새로고침 시 이미 신청한 강의가 장바구니에 다시 표시됨을 확인.
2. **Error 2 테스트**: 우측 관제 패널에서 `⚡ 수강신청 취소 후 대기자 자동 승인 (Error 2)` 클릭 ➔ 0.5초 후 취소 응답 ➔ 4초 후 대기자 자동 승인 응답 완료 ➔ 내 수강 목록(취소됨)과 강의 상세(수강중) 간 상태 불일치 확인.
3. **Error 3 테스트**: 좌측 사이드바에서 `인기순` 정렬 선택 ➔ 최상단 강의의 수강신청 클릭 ➔ UI 알림 상단 강의명과 실제 백엔드에 저장된 신청 강의 ID가 상이함을 확인.
4. **Error 4 테스트**: 중앙 수강신청 완료 대장에서 `🗑️ 수강 취소/삭제` 클릭 ➔ 대장에서는 삭제되나 강의 카드 수강 인원(enrolledCount) 및 정원 그래프 수치가 유지됨을 확인.
5. **Error 5 테스트**: 좌측 학과 필터를 `컴퓨터공학과` 선택 직후 `AI융합학부` 선택 ➔ 3초 후 늦은 이전 컴퓨터공학과 결과가 최신 강의 목록을 덮어씀을 확인.
6. **Error 6 테스트**: 상단 로그인 학생을 `김코딩 (컴공 3학년)`에서 `이알고 (컴공 2학년)`로 전환 ➔ 강의 목록은 B로 바뀌나 상단 KPI 신청 학점은 A 데이터로 잔존함을 확인.
7. **Error 7 테스트**: 상단 계정을 `박조교 (학과 조교)`로 전환 후 `🔒 학과 조교의 강의 정원 변경 시도` 클릭 ➔ UI/API는 HTTP 403 오류 반환 ➔ 백엔드 콘솔 로그에는 SUCCESS (200 OK)로 잘못 작성됨을 확인.
8. **Error 8 테스트**: 우측 하단 강의 정보 수정 패널에서 담당 교수 포함 입력 후 `강의 정보 저장` 클릭 ➔ 토스트는 성공으로 표시되나 새로고침 시 담당 교수만 수정되지 않았음을 확인.
