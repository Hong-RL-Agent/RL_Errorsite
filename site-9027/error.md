🔍 SITE-9023 핵심 오류 및 분석 포인트
1. 불완전한 상태 복구 (Partial Recovery Flaw) - [핵심 함정]
가장 치명적인 논리 결함입니다. 장애 상황을 해결하기 위해 만든 '복구 로직'이 근본 원인을 해결하지 못합니다.

코드 결함: this.stock += 10; (재고만 단순히 추가함)

상세 원인: 현재 가용 재고(available)는 현재고 - 미출고 주문량으로 계산됩니다. 하지만 복구 버튼을 눌렀을 때 현재고만 늘리고 미출고 주문량(pendingOrders)은 그대로 방치합니다.

결과: 복구 후에도 가용 재고는 여전히 마이너스이거나, 주문량을 감당하지 못하는 상태로 남습니다.

2. 상태 코드와 실제 데이터의 불일치 (Status Discrepancy)
시스템은 "성공"이라고 외치지만, 데이터는 여전히 "장애"인 상태를 기만하는 오류입니다.

코드 결함: API 응답에서 "message": "자동 재고 복구 완료"와 함께 성공 메시지를 보냅니다.

현상: 사용자는 메시지만 보고 문제가 해결된 줄 알지만, 화면의 숫자는 여전히 빨간색(마이너스)으로 표시됩니다.

훈련 포인트: 에이전트가 "SUCCESS" 메시지에 속지 않고, 화면의 숫자 변화와 API 응답 데이터의 논리적 모순을 잡아내는지 테스트합니다.

3. 가용성 계산 로직의 투명성 결함
계산 공식이 백엔드에 숨겨져 있어, 에이전트가 여러 번 시도해 보며 공식을 유추해야 합니다.

현상: 단순 재고 수량만 보여주는 게 아니라 available이라는 파생 데이터를 보여줌으로써, 에이전트가 stock과 pendingOrders 사이의 상관관계를 분석하도록 유도합니다.
