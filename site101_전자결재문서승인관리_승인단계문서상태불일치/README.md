## 📋 정상 기능 요약

- **전자결재 통합 관제 대장**: 40건의 문서 기안, 검토, 결재요청, 승인, 반려 상태 관리.
- **임직원 & 결재선 설정**: 30명 임직원의 8개 부서 배치 및 35건의 다단계 결재선 타임라인 설정.
- **결재 의견 & 감사 로그**: 60건의 결재권자 검토 의견 및 80건의 전사 전자결재 감사 로그 제공.
- **기안/검토/승인 직급 권한 관리**: DRAFTER, REVIEWER, APPROVER 권한별 문서 승인 프로세스.

## ⚠️ 의도적으로 삽입된 8가지 복합 오류 목록

1. **Frontend + Backend 요청 순서 충돌**
   - **설명**: 결재선을 변경(3초 지연 완료)한 직후 문서 상태를 결재요청('PENDING')으로 변경(0.1초 완료)하면, 문서 상태 변경 API는 먼저 완료되나 3초 뒤 완료되는 결재선 변경 API가 요청 시작 시점의 구 DB 스냅샷(이전 결재선)을 덮어써 저장하여 새로고침 시 문서 상세 결재선과 결재 대기 목록의 결재자가 서로 달라집니다.

2. **Backend + JSON DB 상태 충돌**
   - **설명**: 문서 반려 API(0.5초 완료)를 호출한 직후 승인 의견 작성 API를 호출(4초 지연 완료)하면, 반려는 성공하지만 늦게 완료된 승인 의견 요청이 반려된 문서를 다시 PENDING 승인대기 상태로 복원시킵니다. 문서 목록에서는 반려, 활동 로그에서는 승인 의견이 추가된 승인대기 문서로 표시됩니다.

3. **Frontend 정렬 인덱스 오류**
   - **설명**: 결재 대기 문서 목록을 마감일순/중요도순으로 정렬한 뒤 승인 버튼을 누르면 UI 알림은 클릭한 문서 제목으로 뜨지만, 백엔드 저장 데이터는 정렬 전 원본 배열의 다른 문서 ID에 연결되는 결함입니다.

4. **통계 집계 불일치**
   - **설명**: 승인 완료 로그를 삭제(`DELETE /api/activity-logs/:id`) 처리하여 활동 로그 목록에서 소거하더라도, 부서별 승인 건수(`signStats.approvedCount`), 평균 처리 시간, 대시보드 결재 완료율 수치에는 차감되지 않고 계속 잔존합니다.

5. **Network stale response 오류**
   - **설명**: 부서 필터('경영지원부' 3초 지연 ➔ 'IT개발부' 0.2초 완료)와 문서 상태 필터를 빠르게 변경 시 오래된 응답(경영지원부)이 최신 문서 목록을 덮어써 문서 목록은 오래된 필터 결과, 오른쪽 결재 요약은 최신 필터 기준 수치로 서로 불일치합니다.

6. **Session + Cache 잔존 오류**
   - **설명**: 직원 A가 결재 대기 문서 상세를 본 뒤 직원 B로 로그인하면 문서 목록은 B 권한 기준으로 바뀌지만, 상단 결재 대기 개수 및 최근 문서 결재선 요약 캐시(`cachedPendingCount`, `cachedRecentDoc`)는 A 데이터가 남아 노출됩니다.

7. **Backend 권한 로그 오류**
   - **설명**: 권한 없는 직원(role !== 'APPROVER')이 최종 승인 API(`POST /api/documents/:id/approve-unauthorized`)를 호출하면 HTTP 403을 반환하지만, 서버 내부 활동 로그에는 '최종 승인 성공 (FINAL APPROVAL COMPLETED SUCCESSFULLY - 200 OK)'으로 잘못 기록됩니다.

8. **부분 저장 오류**
   - **설명**: 문서 수정 모달/패널에서 제목, 긴급 여부, 첨부파일명을 동시에 수정하면 백엔드 data.json에는 제목과 긴급 여부만 저장되고 첨부파일명은 이전 값을 유지하지만, 프론트엔드는 세 항목 모두 수정 성공한 것으로 표시합니다.

## 🧪 테스트 시나리오

1. **Error 1 테스트**: 우측 관제 패널에서 지정 결재자 변경 선택 후 `결재선 변경 후 즉시 결재요청 (Error 1)` 클릭 ➔ 0.1초 후 결재요청 응답 ➔ 3초 후 결재선 변경 응답 완료 ➔ 새로고침 시 이전 결재선으로 롤백 저장됨을 확인.
2. **Error 2 테스트**: 우측 관제 패널에서 `⚡ 문서 반려 후 승인 의견 연쇄 제출 (Error 2)` 클릭 ➔ 0.5초 후 문서 반려 응답 ➔ 4초 후 승인 의견 제출 응답 완료 ➔ 반려된 문서가 PENDING 승인대기 상태로 복원됨을 확인.
3. **Error 3 테스트**: 좌측 사이드바에서 `결재 마감일 임박순` 정렬 선택 ➔ 최상단 문서의 `상세` 클릭 ➔ UI 상단 문서ID와 우측 관제 패널의 기안자/첨부파일 정보가 상이함을 확인.
4. **Error 4 테스트**: 중앙 결재 감사 로그에서 `🗑️ 감사 로그 삭제` 클릭 ➔ 대장에서는 삭제되나 결재 완료율 및 평균 처리시간 수치가 유지됨을 확인.
5. **Error 5 테스트**: 좌측 부서 필터를 `경영지원부` 선택 직후 `IT개발부` 선택 ➔ 3초 후 늦은 이전 경영지원부 결과가 최신 IT개발부 문서 목록을 덮어씀을 확인.
6. **Error 6 테스트**: 상단 로그인 결재권자를 `김동남 대리`에서 `박바캉스 부장`으로 전환 ➔ 문서 목록은 B로 바뀌나 상단 KPI 대기 건수는 A 데이터로 잔존함을 확인.
7. **Error 7 테스트**: 상단 계정을 일반 사원으로 테스트 시 `🔒 권한 없는 일반 직원의 최종 승인 시도` 클릭 ➔ UI/API는 HTTP 403 오류 반환 ➔ 백엔드 콘솔 로그에는 SUCCESS (200 OK)로 잘못 작성됨을 확인.
8. **Error 8 테스트**: 우측 하단 문서 정보 수정 패널에서 첨부파일명 포함 입력 후 `문서 정보 저장` 클릭 ➔ 토스트는 성공으로 표시되나 새로고침 시 첨부파일명만 수정되지 않았음을 확인.
