### SEC-426: 레시피 작성 폼의 클라이언트/서버 검증 불일치
* **SEC ID:** `SEC-426`
* **오류 이름:** 레시피 작성 폼의 서버 입력 검증 부재
* **오류 유형:** validation / server-validation-mismatch
* **발생 조건:** 레시피 작성 화면에서 필수 항목(제목, 재료, 조리 순서)을 입력하지 않고 제출하거나 비정상적인 페이로드를 전달할 때
* **정상 동작:** 필수 항목이 누락된 경우 400 Bad Request 응답과 함께 "필수 항목을 모두 입력해주세요" 오류를 반환해야 함
* **현재 동작:** 백엔드에서 null/empty 유효성 검사를 수행하지 않아 빈 제목이나 기본값으로 레시피가 생성되어 데이터베이스에 등록됨
* **관련 API:** `POST /api/recipes`
* **관련 UI:** RecipeEditor 페이지의 [레시피 등록] 버튼
* **관찰 가능한 결과:** 빈 폼으로 등록해도 "(제목 없는 레시피)"라는 항목이 성공적으로 생성되어 목록에 추가됨
* **PPO 탐색 흐름:** `레시피 작성 진입` → `입력란 공란 유지` → `등록 클릭` → `생성된 빈 레시피 확인`

### SEC-427: 레시피 정렬 기준과 실제 목록 순서 불일치
* **SEC ID:** `SEC-427`
* **오류 이름:** 레시피 정렬 기준과 실제 목록 순서 불일치
* **오류 유형:** sorting / sort-state-mismatch
* **발생 조건:** 레시피 목록 화면에서 정렬 기준(인기순, 최신순, 조리시간순, 이름순)을 변경할 때
* **정상 동작:** 선택한 정렬 기준에 맞추어 레시피 카드들의 순서가 오름차순/내림차순으로 즉시 재정렬되어야 함
* **현재 동작:** UI 드롭다운은 '조리시간순' 등으로 변경되지만 서버는 여전히 기본 인기순(likes) 정렬 결과를 반환함
* **관련 API:** `GET /api/recipes?sort=cookingTime`
* **관련 UI:** Recipes 페이지의 정렬 선택 셀렉트 박스
* **관찰 가능한 결과:** 조리시간순을 선택했음에도 불구하고 10분, 15분 레시피가 아닌 인기도가 높은 50분 포카치아 레시피가 상단에 노출됨
* **PPO 탐색 흐름:** `레시피 목록 조회` → `정렬을 조리시간순으로 변경` → `상단 노출 카드의 조리시간 비교`

### SEC-428: 레시피 편집 자동저장 데이터 손실
* **SEC ID:** `SEC-428`
* **오류 이름:** 레시피 편집 중 디바운스 자동저장 데이터 유실
* **오류 유형:** autosave / debounce-save-loss
* **발생 조건:** 레시피 수정 페이지에서 텍스트(제목, 재료 등)를 빠르게 연속 수정한 후 자동저장이 발생할 때
* **정상 동작:** 사용자가 입력을 멈추면 디바운스 후 최종 입력된 문자열이 온전히 서버로 전달되어 저장되어야 함
* **현재 동작:** 연속 입력 시 이전 타이머 취소 과정에서 최종 변경 내용이 덮어씌워지거나 누락되어 불완전한 상태로 저장됨
* **관련 API:** `PATCH /api/recipes/:id`
* **관련 UI:** RecipeEditor 페이지의 자동저장 인디케이터 (저장 중... / 저장 완료)
* **관찰 가능한 결과:** "토마토 바질 파스타"로 수정한 후 타 페이지로 이동했다가 돌아오면 이전 글자인 "토마토"만 저장되어 있음
* **PPO 탐색 흐름:** `레시피 수정 진입` → `텍스트 빠르게 변경` → `자동저장 확인` → `페이지 이동 후 재방문하여 변경사항 확인`

### SEC-429: 삭제된 레시피의 식단 캘린더 참조 잔존
* **SEC ID:** `SEC-429`
* **오류 이름:** 삭제된 레시피가 식단 캘린더에 dangling reference로 잔존
* **오류 유형:** referential-integrity / dangling-reference
* **발생 조건:** 식단 캘린더에 등록되어 있던 특정 레시피(예: 101번 토마토 바질 파스타)를 삭제한 후 식단 캘린더를 조회할 때
* **정상 동작:** 레시피가 삭제되면 해당 레시피를 참조하고 있던 식단(mealPlans) 항목도 함께 삭제되거나 빈 슬롯으로 초기화되어야 함
* **현재 동작:** 레시피 데이터만 삭제되고 식단 캘린더 테이블의 참조 레코드는 그대로 남아 고아 객체(dangling reference)가 발생함
* **관련 API:** `DELETE /api/recipes/:id`, `GET /api/meal-plans`
* **관련 UI:** RecipeDetail 페이지의 [삭제] 버튼, MealPlanner 페이지의 주간 식단 캘린더
* **관찰 가능한 결과:** 식단 캘린더에 "토마토 바질 파스타 (삭제된 레시피)"라는 비정상 참조 상태가 지속 노출됨
* **PPO 탐색 흐름:** `식단 캘린더 확인` → `해당 레시피 상세 진입 후 삭제` → `식단 캘린더 재방문하여 잔존 참조 확인`

### SEC-430: 특수문자 검색어 처리 오류
* **SEC ID:** `SEC-430`
* **오류 이름:** 특수문자 포함 검색어의 URL 쿼리 인코딩 누락
* **오류 유형:** input-handling / query-encoding
* **발생 조건:** 검색창에 `&`, `%` 등의 특수문자가 포함된 레시피명(예: `토마토 & 바질`)을 입력하고 검색할 때
* **정상 동작:** 특수문자가 안전하게 URL 인코딩(`%26`)되어 백엔드에서 하나의 단일 검색어로 정확히 인식되어야 함
* **현재 동작:** 프론트엔드에서 인코딩 없이 전달하여 앰퍼샌드(&)가 쿼리 구분자로 해석되어 뒤쪽 단어가 유실되고 앞쪽 단어로만 검색됨
* **관련 API:** `GET /api/recipes?search=토마토 & 바질`
* **관련 UI:** RecipeFilter 검색창 및 검색 버튼
* **관찰 가능한 결과:** `토마토 & 바질`을 검색했으나 `토마토`로 시작하는 모든 항목이 검색되거나 예상치 못한 결과 수가 반환됨
* **PPO 탐색 흐름:** `검색창에 '토마토 & 바질' 입력` → `검색 실행` → `요청 쿼리 및 검색 결과 일치 여부 확인`
