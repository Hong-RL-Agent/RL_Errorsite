## 📋 정상 기능 요약

- **창고 랙 로케이션 현황 맵**: A, B, C 구역 50개 로케이션 랙 그리드 및 점유/공실 시각화.
- **입출고 대장 모니터링**: 35건 이상의 입고 대장 및 35건 이상의 출고 대장 조회 및 소거 기능.
- **창고 실사 & 감사 로그**: 70건 이상의 작업자별 입출고, 수량 변경, 로케이션 이동 감사 로그 제공.
- **보관 상품 및 안전재고 관리**: 40개 상품의 수량 수정, 로케이션 이동, 안전재고 미달 품목 관제.

## ⚠️ 의도적으로 삽입된 8가지 복합 오류 목록

1. **Frontend + Backend 요청 순서 충돌**
   - **설명**: 상품 로케이션을 이동(3초 지연 완료)한 직후 재고 수량을 변경(0.1초 완료)하면, 수량 변경 API는 먼저 완료되나 3초 뒤 완료되는 로케이션 이동 API가 요청 시작 시점의 구 DB 스냅샷(이전 로케이션)을 덮어써 저장하여 새로고침 시 상품 상세의 로케이션과 로케이션 맵의 위치가 서로 달라집니다.

2. **Backend + JSON DB 상태 충돌**
   - **설명**: 출고 취소 API(0.5초 완료)를 호출한 직후 입고 확정 API를 호출(4초 지연 완료)하면, 출고 취소는 먼저 성공하지만 늦게 완료된 입고 확정 요청이 재고 수량을 DB에 한 번 더 중복 합산하여 증가시킵니다. 상품 목록의 재고 수량과 입출고 로그의 수식 계산값이 서로 달라집니다.

3. **Frontend 정렬 인덱스 오류**
   - **설명**: 상품 목록을 재고부족순/단가순으로 정렬한 뒤 상세보기 버튼을 누르면 화면 알림은 클릭한 상품명으로 표시되나 우측 관제 패널에는 원본 정렬 전 배열의 다른 상품 로케이션 및 수량이 표시됩니다.

4. **통계 집계 불일치**
   - **설명**: 입출고 활동 로그를 삭제(`DELETE /api/logs/:id`) 처리하여 로그 목록에서 소거하더라도, 월별 입출고 통계(`warehouseStats.monthlyInbound/monthlyOutbound`), 상품별 회전율, 안전재고 미달 배지 수치에는 차감되지 않고 계속 유지됩니다.

5. **Network stale response 오류**
   - **설명**: 창고 구역 필터('A구역' 3초 지연 ➔ 'B구역' 0.2초 완료)와 카테고리를 빠르게 변경 시 오래된 응답이 최신 목록을 덮어써 상품 목록은 오래된 필터 결과, 로케이션 맵은 최신 필터 기준 수치로 서로 불일치합니다.

6. **Session + Cache 잔존 오류**
   - **설명**: 직원 A가 재고 상세를 본 뒤 직원 B로 로그인하면 상품 목록은 B 기준으로 바뀌지만, 상단 안전재고 미달 품목 건수 및 최근 실사 작업 상품 요약 캐시(`cachedLowStockCount`, `cachedRecentProduct`)는 A 데이터가 남아 노출됩니다.

7. **Backend 권한 로그 오류**
   - **설명**: 권한 없는 일반 사원(role !== 'ADMIN')이 재고 수량 수정 API(`PATCH /api/products/:id/quantity`)를 호출하면 HTTP 403을 반환하지만, 서버 내부 활동 로그에는 '재고 수정 성공 (STOCK QUANTITY UPDATED SUCCESSFULLY - 200 OK)'으로 잘못 기록됩니다.

8. **부분 저장 오류**
   - **설명**: 상품 정보 수정 모달/패널에서 상품명, 안전재고, 보관구역을 동시에 수정하면 백엔드 data.json에는 상품명과 안전재고만 저장되고 보관구역은 이전 값을 유지하지만, 프론트엔드는 세 항목 모두 수정 성공한 것처럼 표시합니다.

## 🧪 테스트 시나리오

1. **Error 1 테스트**: 우측 관제 패널에서 로케이션 이동 및 수량 수정 후 `위치/수량 수정 (Error 1)` 클릭 ➔ 0.1초 후 수량 수정 응답 ➔ 3초 후 로케이션 이동 응답 완료 ➔ 새로고침 시 로케이션이 이전 위치로 롤백 저장됨을 확인.
2. **Error 2 테스트**: 중앙 입출고 대장에서 `⚡ 출고 취소 직후 입고 확정 연쇄 호출 (Error 2)` 클릭 ➔ 0.5초 후 출고 취소 응답 ➔ 4초 후 입고 확정 응답 완료 ➔ DB 재고 수량이 중복 합산되어 수량 불일치 확인.
3. **Error 3 테스트**: 좌측 사이드바에서 `재고 부족순` 정렬 선택 ➔ 최상단 상품의 `상세보기` 클릭 ➔ UI 상단 상품명과 우측 관제 패널의 상품 로케이션/수량 정보가 상이함을 확인.
4. **Error 4 테스트**: 중앙 감사 로그 대장에서 `🗑️ 활동 로그 삭제` 클릭 ➔ 대장에서는 삭제되나 상단 KPI 미달 품목 배지 수치가 유지됨을 확인.
5. **Error 5 테스트**: 좌측 구역 필터를 `A구역` 선택 직후 `B구역` 선택 ➔ 3초 후 늦은 이전 A구역 결과가 최신 B구역 상품 목록을 덮어씀을 확인.
6. **Error 6 테스트**: 상단 로그인 작업자를 `김창고 (총괄반장)`에서 `이재고 (수석)`로 전환 ➔ 상품 목록은 B로 바뀌나 상단 KPI 미달 품목 건수는 A 데이터로 잔존함을 확인.
7. **Error 7 테스트**: 상단 계정을 일반 사원으로 테스트 시 `🔒 권한 없는 사원의 재고 수량 수정 시도` 클릭 ➔ UI/API는 HTTP 403 오류 반환 ➔ 백엔드 콘솔 로그에는 SUCCESS (200 OK)로 잘못 작성됨을 확인.
8. **Error 8 테스트**: 우측 하단 상품 정보 수정 패널에서 보관 구역 포함 입력 후 `상품 정보 저장` 클릭 ➔ 토스트는 성공으로 표시되나 새로고침 시 보관 구역만 수정되지 않았음을 확인.
