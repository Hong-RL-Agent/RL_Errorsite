1. **백엔드 실행**:


## 📋 정상 기능 요약

- **스마트팜 구역 평면도**: 12개 농장 구역(온실, 수경재배, 스마트노지 등) 및 환경 상태 모니터링.
- **실시간 센서 현황**: 60개 이상의 온도, 습도, 토양수분, 조도, CO2농도 센서 측정값 모니터링.
- **관수 작업 수행 관제**: 40개 이상의 관수, 엽면 살수, 양액 분무 제어 이력 관리.
- **센서 이상 알림 대장**: 25개 이상의 경고, 위험, 주의 단계 센서 이상 알림 모니터링.

## ⚠️ 의도적으로 삽입된 8가지 복합 오류 목록

1. **Frontend + Backend 요청 순서 충돌**
   - **설명**: 관수 예약 시간을 변경(3초 지연 완료)한 직후 관수량을 변경(0.1초 완료)하면, 관수량 변경 API는 먼저 성공하지만 3초 뒤 완료되는 예약 시간 변경 API 내부에 이전 관수량(`irrigationVolume`)이 동봉 저장되어 새로고침 시 화면 관수량과 DB 관수량이 서로 달라집니다.

2. **Backend + JSON DB 상태 충돌**
   - **설명**: 관수 작업 취소 API(0.5초 완료)를 호출한 직후 센서 이상 알림 처리 API를 호출(4초 지연 완료)하면, 취소 요청은 먼저 성공하지만 늦게 완료된 알림 처리 요청이 취소된 작업을 다시 'IN_PROGRESS'(진행중) 상태로 재활성화시킵니다. 작업 목록에서는 취소됨, 알림 상세에서는 진행중으로 표시됩니다.

3. **Frontend 정렬 인덱스 오류**
   - **설명**: 작물 목록을 위험도순으로 정렬한 뒤 상세보기 버튼을 누르면 화면 상단 작물명은 클릭한 작물명으로 표시되나 우측 상세 패널의 센서값과 작업 로그는 원본 정렬 전 배열의 다른 작물 기준 데이터가 노출됩니다.

4. **통계 집계 불일치**
   - **설명**: 센서 이상 로그를 삭제(`DELETE /api/alerts/:id`) 처리하여 이력 대장에서 소거하더라도, 구역별 이상 발생률(`zoneAlertRates`), 작물별 위험도, 대시보드 경고 개수 수치에는 차감되지 않고 계속 유지됩니다.

5. **Network stale response 오류**
   - **설명**: 구역 필터('ZN-A1' 3초 지연 ➔ 'ZN-A2' 0.2초 완료)와 센서 카테고리를 빠르게 변경 시 오래된 응답이 최신 목록을 덮어써 센서 카드는 오래된 필터 결과, 오른쪽 통계 패널은 최신 필터 기준 수치로 서로 불일치합니다.

6. **Session + Cache 잔존 오류**
   - **설명**: 관리자 A가 특정 농장 구역을 본 뒤 관리자 B로 로그인하면 구역 목록은 B 기준으로 바뀌지만, 상단 위험 알림 개수 및 최근 센서 요약 캐시(`cachedAlertCount`, `cachedRecentSensorSummary`)는 A 데이터가 남아 노출됩니다.

7. **Backend 권한 로그 오류**
   - **설명**: 권한 없는 직원(role !== 'ADMIN')이 관수 작업 실행 API(`POST /api/crops/:id/irrigate`)를 호출하면 HTTP 403을 반환하지만, 서버 내부 활동 로그에는 '관수 실행 성공 (IRRIGATION EXECUTION SUCCESS - 200 OK)'으로 잘못 기록됩니다.

8. **부분 저장 오류**
   - **설명**: 작물 정보 수정 모달/패널에서 작물명, 생육 단계, 담당자를 동시에 수정하면 백엔드 data.json에는 작물명과 생육 단계만 저장되고 담당자는 이전 값을 유지하지만, 프론트엔드는 세 항목 모두 수정 성공한 것처럼 표시합니다.

## 🧪 테스트 시나리오

1. **Error 1 테스트**: 우측 패널에서 예약 시간 변경 입력 후 `시간 변경` 클릭 ➔ 0.1초 후 관수량 변경 응답 ➔ 3초 후 예약 시간 변경 응답이 완료되며 새로고침 시 관수 공급량이 이전 용량으로 롤백됨을 확인.
2. **Error 2 테스트**: 우측 패널에서 `⚡ 관수 취소 후 이상알림 처리` 클릭 ➔ 0.5초 후 취소 응답 ➔ 4초 후 알림 처리 응답이 완료되며 작업 목록(취소됨)과 알림 상세(진행중) 간 상태 불일치 확인.
3. **Error 3 테스트**: 좌측 사이드바에서 `위험도 높은순` 정렬 선택 ➔ 상단 작물의 상세보기 클릭 ➔ UI 상단 작물명과 우측 상세 패널의 센서/작업로그 정보가 상이함을 확인.
4. **Error 4 테스트**: 중앙 이상 알림 대장에서 `🗑️ 삭제` 클릭 ➔ 대장에서는 삭제되나 구역별 이상 발생률 및 대시보드 경고 수치가 유지됨을 확인.
5. **Error 5 테스트**: 좌측 구역 필터를 `A1 온실` 선택 직후 `A2 온실` 선택 ➔ 3초 후 늦은 이전 결과가 최신 센서 목록을 덮어씀을 확인.
6. **Error 6 테스트**: 상단 로그인 관리자를 `김농장 대표`에서 `이재배 과장`으로 전환 ➔ 구역 목록은 B로 바뀌나 상단 KPI 위험 알림 개수는 A 데이터로 잔존함을 확인.
7. **Error 7 테스트**: 상단 계정을 `박센서 팀장 (일반 직원)`으로 전환 후 `🔒 일반 직원의 강제 관수 실행 시도` 클릭 ➔ UI/API는 HTTP 403 오류 반환 ➔ 백엔드 콘솔 로그에는 SUCCESS (200 OK)로 잘못 작성됨을 확인.
8. **Error 8 테스트**: 우측 하단 작물 정보 수정 패널에서 담당자 포함 입력 후 `작물 정보 저장` 클릭 ➔ 토스트는 성공으로 표시되나 새로고침 시 담당자만 수정되지 않았음을 확인.
