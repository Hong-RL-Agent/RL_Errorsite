## 📋 정상 기능 요약

- **콜센터 상담 접수 관제 대장**: 45건의 인바운드 통화 접수, 신규, 배정대기, 처리중, 보류, 완료, 재문의 관제.
- **등록 고객 & 상담원 팀 배치**: 35명 등록 고객 등급/이력 및 18명 상담원 팀별 전담 처리 실적 관리.
- **VOC 카테고리 & 상담 메모 대장**: 10개 VOC 카테고리(배송지연, 결제오류 등) 및 70건의 상담 메모 이력 관제.
- **활동 로그 & 권한 관제**: 80건의 상담원 배정/상태 변경 활동 로그 및 관리자/상담원 스태프 권한 관리.

## ⚠️ 의도적으로 삽입된 8가지 복합 오류 목록

1. **Frontend + Backend 요청 순서 충돌**
   - **설명**: 상담 상태를 '처리중'(IN_PROGRESS)으로 변경(3초 지연 완료)한 직후 담당 상담원을 변경(0.1초 완료)하면, 담당자 변경 API는 먼저 완료되나 3초 뒤 완료되는 상태 변경 API가 요청 시작 시점의 구 DB 스냅샷(이전 담당자)을 덮어써 저장하여 새로고침 시 상담 목록의 담당자와 상담 상세의 담당자가 서로 달라집니다.

2. **Backend + JSON DB 상태 충돌**
   - **설명**: 상담 완료 API(0.5초 완료)를 호출한 직후 고객이 재문의 등록 API를 호출(4초 지연 완료)하면, 완료 요청은 성공하지만 늦게 완료된 재문의 요청이 완료된 상담을 다시 IN_PROGRESS 처리중 상태로 복원시킵니다. 상담 목록에서는 완료, 고객 이력에서는 처리중 재문의로 표시됩니다.

3. **Frontend 정렬 인덱스 오류**
   - **설명**: 상담 목록을 대기시간순/우선순위순으로 정렬한 뒤 상세 보기 버튼을 누르면 UI 알림은 클릭한 상담 번호로 뜨지만, 백엔드 저장 데이터는 정렬 전 원본 배열의 다른 상담 ID에 연결되는 결함입니다.

4. **통계 집계 불일치**
   - **설명**: 상담 메모를 삭제(`DELETE /api/memos/:id`) 처리하여 상담 상세에서는 메모가 소거되더라도, 상담원별 처리량, VOC 카테고리별 건수, 대시보드 완료율(`callStats.completionRate`) 수치에는 차감되지 않고 계속 잔존합니다.

5. **Network stale response 오류**
   - **설명**: VOC 카테고리 필터('배송지연' 3초 지연 ➔ '결제오류' 0.2초 완료)와 상담 상태 필터를 빠르게 변경 시 오래된 응답(배송지연)이 최신 상담 목록을 덮어써 상담 목록은 오래된 필터 결과, 오른쪽 VOC 요약은 최신 필터 기준 수치로 서로 불일치합니다.

6. **Session + Cache 잔존 오류**
   - **설명**: 상담원 A가 고객 상세를 본 뒤 상담원 B로 로그인하면 상담 목록은 B 담당 기준으로 바뀌지만, 상단 미처리 상담 수 및 최근 고객 상세 캐시(`cachedUnprocessedCalls`, `cachedRecentCustomer`)는 A 데이터가 남아 노출됩니다.

7. **Backend 권한 로그 오류**
   - **설명**: 권한 없는 상담원(role !== 'ADMIN')이 다른 팀 상담 상태 변경 API(`PATCH /api/calls/:id/status-unauthorized`)를 호출하면 HTTP 403을 반환하지만, 서버 내부 활동 로그에는 '상담 상태 변경 성공 (CALL STATUS CHANGED SUCCESSFULLY - 200 OK)'으로 잘못 기록됩니다.

8. **부분 저장 오류**
   - **설명**: 고객 정보 수정 모달/패널에서 연락처, 등급, 최근 문의 요약을 동시에 수정하면 백엔드 data.json에는 연락처와 최근 문의 요약만 저장되고 등급은 이전 값을 유지하지만, 프론트엔드는 세 항목 모두 수정 성공한 것으로 표시합니다.

## 🧪 테스트 시나리오

1. **Error 1 테스트**: 우측 관제 패널에서 상담 상태 변경 선택 후 `상태 변경 후 즉시 담당자 변경 (Error 1)` 클릭 ➔ 0.1초 후 담당자 변경 응답 ➔ 3초 후 상태 변경 응답 완료 ➔ 새로고침 시 이전 담당자로 롤백 저장됨을 확인.
2. **Error 2 테스트**: 우측 관제 패널에서 `⚡ 상담 완료 처리 후 재문의 연쇄 등록 (Error 2)` 클릭 ➔ 0.5초 후 상담 완료 응답 ➔ 4초 후 재문의 등록 응답 완료 ➔ 완료된 상담이 IN_PROGRESS 처리중 상태로 복원됨을 확인.
3. **Error 3 테스트**: 좌측 사이드바에서 `대기 시간 긴순` 정렬 선택 ➔ 최상단 상담의 `상세` 클릭 ➔ UI 상단 상담ID와 우측 관제 패널의 고객명/문의내용 정보가 상이함을 확인.
4. **Error 4 테스트**: 중앙 상담 메모 대장에서 `🗑️ 메모 삭제` 클릭 ➔ 대장에서는 삭제되나 완료율 및 상담원 처리량 수치가 유지됨을 확인.
5. **Error 5 테스트**: 좌측 VOC 카테고리 필터를 `배송지연` 선택 직후 `결제오류` 선택 ➔ 3초 후 늦은 이전 배송지연 결과가 최신 결제오류 상담 목록을 덮어씀을 확인.
6. **Error 6 테스트**: 상단 로그인 상담원을 `김상담 수석`에서 `이응대 전담`으로 전환 ➔ 상담 목록은 B로 바뀌나 상단 KPI 미처리 대기 건수는 A 데이터로 잔존함을 확인.
7. **Error 7 테스트**: 상단 계정을 일반 스태프로 테스트 시 `🔒 타 팀 상담원의 상담 상태 변경 시도` 클릭 ➔ UI/API는 HTTP 403 오류 반환 ➔ 백엔드 콘솔 로그에는 SUCCESS (200 OK)로 잘못 작성됨을 확인.
8. **Error 8 테스트**: 우측 하단 고객 정보 수정 패널에서 등급 포함 입력 후 `고객 정보 저장` 클릭 ➔ 토스트는 성공으로 표시되나 새로고침 시 등급만 수정되지 않았음을 확인.
