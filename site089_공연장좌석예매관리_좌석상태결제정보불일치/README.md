## 📋 정상 기능 요약

- **공연장 실시간 좌석배치도**: 120개 이상의 VIP, R, S 등급별 좌석 현황 및 메인 무대 조망.
- **상영 공연 관제**: 18개 이상의 뮤지컬, 클래식, 연극, 서커스, 발레, 재즈 공연 정보 및 인기 지수 조회.
- **예매 및 내 티켓 관리**: 35개 이상의 예매 데이터 발권, 좌석 변경, 결제 금액 모니터링.
- **티켓 발권 이력 로그**: 50개 이상의 발권 및 상태 변동 이력 로그 모니터링.

## ⚠️ 의도적으로 삽입된 8가지 복합 오류 목록

1. **Frontend + Backend 요청 순서 충돌**
   - **설명**: 좌석을 변경(3초 지연 완료)한 직후 예매자 정보를 수정(0.1초 완료)하면, 예매자 정보 수정 API는 먼저 성공하지만 3초 뒤 완료되는 좌석 변경 API 내부에 이전 예매자명(`userName`)이 동봉 저장되어 새로고침 시 예매 확인 화면의 예매자명과 티켓 상세의 예매자명이 서로 달라집니다.

2. **Backend + JSON DB 상태 충돌**
   - **설명**: 예매 취소 API(0.5초 완료)를 호출한 직후 관리자 티켓 발권 API를 호출(4초 지연 완료)하면, 취소 요청은 먼저 성공하지만 늦게 완료된 발권 요청이 취소된 예매를 다시 'ISSUED'(발권완료) 상태로 재활성화시킵니다. 내 티켓에서는 취소됨, 관리자 좌석 현황에서는 발권완료로 표시됩니다.

3. **Frontend 정렬 인덱스 오류**
   - **설명**: 공연 목록을 인기순으로 정렬한 뒤 예매하기 버튼을 누르면 화면 상단 제목은 클릭한 공연명으로 표시되나 중앙 좌석 선택 화면의 공연 id와 가격은 원본 정렬 전 배열의 다른 공연 기준 데이터가 노출됩니다.

4. **통계 집계 불일치**
   - **설명**: 예매 데이터를 삭제(`DELETE /api/reservations/:id`) 처리하여 대장에서 소거하더라도, 공연별 예매율(`seatOccupancyRate`), 점유율, 매출 통계 수치에는 차감되지 않고 계속 유지됩니다.

5. **Network stale response 오류**
   - **설명**: 공연 날짜 필터('2026-08-15' 3초 지연 ➔ '2026-08-16' 0.2초 완료)와 좌석 등급 필터를 빠르게 변경 시 오래된 응답이 최신 목록을 덮어써 좌석도는 오래된 좌석 상태, 오른쪽 가격 요약 패널은 최신 필터 기준 가격으로 서로 불일치합니다.

6. **Session + Cache 잔존 오류**
   - **설명**: 사용자 A가 내 티켓을 본 뒤 사용자 B로 로그인하면 티켓 목록은 B 기준으로 바뀌지만, 상단 예매 개수 및 최근 관람 예정 공연 요약 캐시(`cachedReservationCount`, `cachedUpcomingShowSummary`)는 A 데이터가 남아 노출됩니다.

7. **Backend 권한 로그 오류**
   - **설명**: 권한 없는 직원(role !== 'ADMIN')이 티켓 발권 API(`POST /api/reservations/:id/issue`)를 호출하면 HTTP 403을 반환하지만, 서버 내부 활동 로그에는 '티켓 발권 성공 (TICKET ISSUE SUCCESS - 200 OK)'으로 잘못 기록됩니다.

8. **부분 저장 오류**
   - **설명**: 공연 정보 수정 모달/패널에서 공연 시간, 장소, 좌석 가격을 동시에 수정하면 백엔드 data.json에는 공연 시간과 좌석 가격만 저장되고 장소는 이전 값을 유지하지만, 프론트엔드는 세 항목 모두 수정 성공한 것처럼 표시합니다.

## 🧪 테스트 시나리오

1. **Error 1 테스트**: 우측 패널에서 예매자 성함 변경 입력 후 `좌석 변경` 클릭 ➔ 0.1초 후 예매자 변경 응답 ➔ 3초 후 좌석 변경 응답이 완료되며 새로고침 시 예매 확인 화면과 티켓 상세 간 예매자명 불일치 확인.
2. **Error 2 테스트**: 우측 패널에서 `⚡ 예매 취소 후 티켓 재발권` 클릭 ➔ 0.5초 후 취소 응답 ➔ 4초 후 발권 응답이 완료되며 내 티켓(취소됨)과 관리자 좌석 현황(발권완료) 간 상태 불일치 확인.
3. **Error 3 테스트**: 좌측 사이드바에서 `인기순` 정렬 선택 ➔ 상단 공연의 예매하기 클릭 ➔ UI 상단 공연명과 중앙 좌석 선택 화면의 공연 ID/가격 정보가 상이함을 확인.
4. **Error 4 테스트**: 중앙 내 티켓 대장에서 `🗑️ 삭제` 클릭 ➔ 대장에서는 삭제되나 공연 예매율 및 매출 통계 수치가 유지됨을 확인.
5. **Error 5 테스트**: 좌측 날짜 필터를 `08-15` 선택 직후 `08-16` 선택 ➔ 3초 후 늦은 이전 결과가 최신 좌석도를 덮어씀을 확인.
6. **Error 6 테스트**: 상단 로그인 사용자를 `김철수 회원`에서 `이영희 회원`으로 전환 ➔ 티켓 목록은 B로 바뀌나 상단 KPI 예매 개수는 A 데이터로 잔존함을 확인.
7. **Error 7 테스트**: 상단 계정을 `안재민 사원 (일반 직원)`으로 전환 후 `🔒 일반 직원의 티켓 발권 시도` 클릭 ➔ UI/API는 HTTP 403 오류 반환 ➔ 백엔드 콘솔 로그에는 SUCCESS (200 OK)로 잘못 작성됨을 확인.
8. **Error 8 테스트**: 우측 하단 공연 정보 수정 패널에서 공연장소 포함 입력 후 `공연 정보 저장` 클릭 ➔ 토스트는 성공으로 표시되나 새로고침 시 공연장소만 수정되지 않았음을 확인.
