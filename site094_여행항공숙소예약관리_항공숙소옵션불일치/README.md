## 📋 정상 기능 요약

- **글로벌 패키지 여행지도 & 항공편 검색**: 18개 여행지 및 30개 항공편의 SVG 서킷 더미 지도 시각화 및 필터링.
- **숙소 & 현지 투어 패키지 옵션**: 25개 5성급/리조트 숙소 및 20개 액티비티/투어 옵션 검색 및 선택.
- **통합 패키지 예약 및 매출 대장**: 30건 이상의 패키지 예약 관리 및 결제 옵션 삭제 기능.
- **예약자 인적사항 & 영권 정보 변경**: 여행자 여권 영문명, 연락처, 특별 요청사항 변경 관리.

## ⚠️ 의도적으로 삽입된 8가지 복합 오류 목록

1. **Frontend + Backend 요청 순서 충돌**
   - **설명**: 예약에서 숙소를 변경(3초 지연 완료)한 직후 항공편을 변경(0.1초 완료)하면, 항공편 변경 API는 먼저 완료되나 3초 뒤 완료되는 숙소 변경 API가 요청 시작 시점의 구 DB 스냅샷(이전 항공편)을 덮어써 저장하여 새로고침 시 예약 요약의 항공편과 내 예약 상세의 항공편이 서로 달라집니다.

2. **Backend + JSON DB 상태 충돌**
   - **설명**: 예약 취소 API(0.5초 완료)를 호출한 직후 여행 옵션 추가 API를 호출(4초 지연 완료)하면, 예약 취소는 먼저 성공하지만 늦게 완료된 옵션 추가 요청이 취소된 예약을 'CONFIRMED'(예약확정) 상태로 다시 바꿔버립니다. 내 예약 목록에서는 취소됨, 관리자 예약 현황에서는 예약확정으로 표시됩니다.

3. **Frontend 정렬 인덱스 오류**
   - **설명**: 숙소 목록을 1박 가격순/평점순으로 정렬한 뒤 숙소 선택 버튼을 누르면 화면 알림은 클릭한 숙소명으로 표시되나 우측 관제 패널에는 원본 정렬 전 배열의 다른 숙소 ID가 저장됩니다.

4. **통계 집계 불일치**
   - **설명**: 여행 옵션을 삭제(`DELETE /api/bookings/:id/options/:optionId`) 처리하여 예약 상세 옵션 목록에서 소거하더라도, 총 예약 금액(`totalPrice`), 옵션별 판매량, 관리자 매출 통계 수치에는 차감되지 않고 계속 유지됩니다.

5. **Network stale response 오류**
   - **설명**: 여행지 필터('다낭' 3초 지연 ➔ '도쿄' 0.2초 완료)를 빠르게 변경 시 오래된 응답이 최신 목록을 덮어써 중앙 항공편 목록은 오래된 필터 결과, 오른쪽 예약 요약은 최신 필터 기준 수치로 서로 불일치합니다.

6. **Session + Cache 잔존 오류**
   - **설명**: 사용자 A가 예약을 본 뒤 사용자 B로 로그인하면 예약 목록은 B 기준으로 바뀌지만, 상단 최근 탐색 여행지 및 예약 예정 건수 요약 캐시(`cachedDestination`, `cachedCount`)는 A 데이터가 남아 노출됩니다.

7. **Backend 권한 로그 오류**
   - **설명**: 권한 없는 직원(role !== 'ADMIN')이 예약 확정 API(`POST /api/bookings/:id/confirm`)를 호출하면 HTTP 403을 반환하지만, 서버 내부 활동 로그에는 '예약 확정 성공 (BOOKING CONFIRMED SUCCESSFULLY - 200 OK)'으로 잘못 기록됩니다.

8. **부분 저장 오류**
   - **설명**: 예약자 정보 수정 모달/패널에서 여권 영문명, 연락처, 요청사항을 동시에 수정하면 백엔드 data.json에는 영문명과 요청사항만 저장되고 연락처는 이전 값을 유지하지만, 프론트엔드는 세 항목 모두 수정 성공한 것처럼 표시합니다.

## 🧪 테스트 시나리오

1. **Error 1 테스트**: 우측 관제 패널에서 숙소 및 항공편 변경 후 `항공/숙소 변경 확정 (Error 1)` 클릭 ➔ 0.1초 후 항공편 변경 응답 ➔ 3초 후 숙소 변경 응답 완료 ➔ 새로고침 시 항공편이 이전 항공편으로 롤백 저장됨을 확인.
2. **Error 2 테스트**: 우측 관제 패널에서 `⚡ 예약 취소 후 여행 옵션 추가 (Error 2)` 클릭 ➔ 0.5초 후 예약 취소 응답 ➔ 4초 후 옵션 추가 응답 완료 ➔ 예약이 취소됨에서 다시 CONFIRMED (예약확정) 상태로 재활성화됨을 확인.
3. **Error 3 테스트**: 좌측 사이드바에서 `1박 가격 낮은순` 정렬 선택 ➔ 최상단 숙소의 `숙소 선택` 클릭 ➔ UI 카드 상단 숙소명과 우측 관제 패널의 예약 숙소 ID 정보가 상이함을 확인.
4. **Error 4 테스트**: 중앙 예약 대장에서 `🗑️ 여행 옵션 삭제` 클릭 ➔ 대장에서는 옵션이 삭제되나 총 예약 금액 및 매출 통계 수치가 유지됨을 확인.
5. **Error 5 테스트**: 좌측 목적지 필터를 `다낭` 선택 직후 `도쿄` 선택 ➔ 3초 후 늦은 이전 다낭 결과가 최신 도쿄 항공편 목록을 덮어씀을 확인.
6. **Error 6 테스트**: 상단 로그인 여행자를 `김동남 (VIP)`에서 `이휴가 (일반)`로 전환 ➔ 내 예약 목록은 B로 바뀌나 상단 KPI 최근 여행지는 A 데이터로 잔존함을 확인.
7. **Error 7 테스트**: 상단 계정을 CS 직원으로 테스트 시 `🔒 CS 사원의 강제 예약 확정 시도` 클릭 ➔ UI/API는 HTTP 403 오류 반환 ➔ 백엔드 콘솔 로그에는 SUCCESS (200 OK)로 잘못 작성됨을 확인.
8. **Error 8 테스트**: 우측 하단 여행자 정보 수정 패널에서 연락처 포함 입력 후 `예약자 정보 저장` 클릭 ➔ 토스트는 성공으로 표시되나 새로고침 시 연락처만 수정되지 않았음을 확인.
