# SQL Injection (Conditional Branching) Vulnerability Report (site017)

본 문서에는 Amore Wedding 웨딩 플래닝 플랫폼(`site017`)의 의도된 SQL Injection 조건 분기 취약점 정보(site017-bug01 ~ site017-bug10)가 기재되어 있습니다.

---

### 1. site017-bug01 (SEC-161)
- **type**: sql-injection
- **발생 API**: `POST /api/login`
- **발생 조건**: 로그인 폼 제출 시 정상 로그인과 SQL 인젝션 분기 marker 입력 결과를 비교합니다.
- **코드상 원인**: 로그인 계정 아이디 매개변수(username)가 쿼리 검증부에 이스케이프 및 바인딩 없이 직접 삽입되어 참/거짓 조건에 따른 로그인 여부가 결정됩니다.
- **PPO 탐지 기준**: 정상 입력 시와 마커 입력 시 로그인 성공 또는 실패 응답 결과가 달라질 시 검출됩니다.

---

### 2. site017-bug02 (SEC-162)
- **type**: sql-injection
- **발생 API**: `POST /api/register`
- **발생 조건**: 회원가입 시 아이디 입력에 분기 마커를 삽입한 후 결과를 비교합니다.
- **코드상 원인**: 회원 가입 ID의 중복 여부 및 데이터 무결성 체크 조건절에 직접 문자열을 결합하여 회원 가입 조건 분기 변조를 초래합니다.
- **PPO 탐지 기준**: 정상 입력값과 마커 입력값 가입 절차 시 생성 성공 응답 데이터 불일치 여부를 비교 검출합니다.

---

### 3. site017-bug03 (SEC-163)
- **type**: sql-injection
- **발생 API**:
  - `POST /api/profile/address` (저장)
  - `GET /api/profile/address` (조회)
- **발생 조건**: 주소지 관리 정보 입력 및 조회 결과 대조 시 SQL 분기 마커를 입력해 비교합니다.
- **코드상 원인**: 주소 검색 조건절(keyword) 입력값이 정제되지 않고 직접 결합되어 타 회원의 비공개 주소지 정보 노출을 야기합니다.
- **PPO 탐지 기준**: 인젝션 구문 삽입에 따른 반환 건수 및 데이터 불일치 여부로 검출합니다.

---

### 4. site017-bug04 (SEC-164)
- **type**: sql-injection
- **발생 API**:
  - `POST /api/coupons` (저장)
  - `GET /api/coupons` (조회)
- **발생 조건**: 할인 쿠폰 키코드 입력 시 조건문을 우회 대조하여 쿠폰 조회를 수행합니다.
- **코드상 원인**: 할인 쿠폰 코드 유효성 검사 쿼리 결합 시 이스케이프를 처리하지 않아 다른 비공개 쿠폰 목록이 노출됩니다.
- **PPO 탐지 기준**: 정상 검색 시와 마커 검색 시 반환되는 쿠폰 리스트 개수의 증감 변화 여부로 검출됩니다.

---

### 5. site017-bug05 (SEC-165)
- **type**: sql-injection
- **발생 API**: `GET /api/venues`
- **발생 조건**: 웨딩홀 목록 정렬 옵션(sort) 매개변수에 인젝션 구문을 기재하고 조회 결과를 대조합니다.
- **코드상 원인**: 정렬 칼럼 및 조건 인자 파라미터가 쿼리에 바인딩 없이 직접 병합되어 조건절 분기가 변형됩니다.
- **PPO 탐지 기준**: 정상 정렬과 인젝션 구문 입력 시의 결과 수량 및 데이터 순서 변화 여부로 검출됩니다.

---

### 6. site017-bug06 (SEC-166)
- **type**: sql-injection
- **발생 API**: `GET /api/venues`
- **발생 조건**: 웨딩홀 페이징 번호(page) 파라미터에 분기 구문을 주입하고 결과를 대조합니다.
- **코드상 원인**: 페이지 번호 계산 인수 바인딩 누락으로 인해 조건절 분기를 다변화시킵니다.
- **PPO 탐지 기준**: 정상 조회와 인젝션 구문 입력 시의 웨딩홀 목록 반환 수량 차이로 검출합니다.

---

### 7. site017-bug07 (SEC-167)
- **type**: sql-injection
- **발생 API**:
  - `POST /api/contracts/upload` (저장)
  - `GET /api/contracts` (조회)
- **발생 조건**: 계약 증빙 서류 파일 이름 및 설명 정보 기재 시 분기 마커를 삽입한 후 파일 목록 조회를 대조합니다.
- **코드상 원인**: 계약서 파일 설명 기입 텍스트 매개변수의 바인딩 변수 생략으로 다른 사용자의 예약 정보 및 계약 기록이 반환됩니다.
- **PPO 탐지 기준**: 인젝션 마커 삽입 여부에 따른 파일 반환 수량 변화 여부로 검출합니다.

---

### 8. site017-bug08 (SEC-168)
- **type**: sql-injection
- **발생 API**:
  - `POST /api/chat` (저장)
  - `GET /api/chat` (조회)
- **발생 조건**: 1:1 상담 채팅 기입란에 인젝션 조건문을 주입하고 대화 기록 조회를 대조합니다.
- **코드상 원인**: 플래너 실시간 채팅 메시지 검색 본문이 쿼리 식에 직접 병합 처리되어 타인의 비공개 대화 히스토리가 전부 노출되는 취약점이 발생합니다.
- **PPO 탐지 기준**: 정상 입력 시와 마커 입력 시 반환되는 채팅 메시지 목록 편차를 감지해 검출합니다.

---

### 9. site017-bug09 (SEC-169)
- **type**: sql-injection
- **발생 API**: `GET /api/notices`
- **발생 조건**: 긴급 공지사항 상세 검색 조회 시 조건 분기를 삽입하여 공지사항 목록 조회를 대조합니다.
- **코드상 원인**: 공지사항 검색 파라미터(keyword)에 인코딩 및 마스킹 없이 쿼리에 직접 병합 처리하여 숨겨진 이벤트 공지사항이 전부 노출됩니다.
- **PPO 탐지 기준**: 정상 검색 키워드와 인젝션 구문 입력 시 반환되는 공지사항 개수의 차이를 비교 검출합니다.

---

### 10. site017-bug10 (SEC-170)
- **type**: sql-injection
- **발생 API**:
  - `POST /api/reviews` (저장)
  - `GET /api/reviews` (조회)
- **발생 조건**: 리뷰 별점 코멘트 입력 시 조건문을 주입하고 리뷰 목록 조회를 대조합니다.
- **코드상 원인**: 리뷰 텍스트 매개변수 바인딩 생략으로 인해 전체 리뷰 목록 조회가 왜곡됩니다.
- **PPO 탐지 기준**: 기입 마커 유무에 따른 반환 리뷰 피드 수량 변화를 기준으로 검출합니다.
