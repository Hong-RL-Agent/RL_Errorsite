## 📋 정상 기능 요약

- **단계별 사전 문진 스태퍼**: Step 1~4 단계형 문진 작성 및 진행률 프로그레스 바 UI.
- **환자 사전 문진 답변 대장**: 45건의 환자별 주요 통증, 진료과, 통증 점수 및 위험도 판정 관제.
- **진료 예약 & 원무 관리**: 35건의 진료 예약 일시, 담당 의사 연동 및 병원 원무 활동 감사 로그 제공.
- **등록 환자 신체 정보 관제**: 30명 환자의 성별, 연령, 키, 몸무게, 복용 중 약물 인적사항 관리.

## ⚠️ 의도적으로 삽입된 8가지 복합 오류 목록

1. **Frontend + Backend 요청 순서 충돌**
   - **설명**: 문진 답변을 수정(3초 지연 완료)한 직후 예약 시간을 변경(0.1초 완료)하면, 예약 시간 변경 API는 먼저 완료되나 3초 뒤 완료되는 문진 답변 수정 API가 요청 시작 시점의 구 DB 스냅샷(이전 예약 시간)을 덮어써 저장하여 새로고침 시 문진 요약과 예약 상세의 시간이 서로 달라집니다.

2. **Backend + JSON DB 상태 충돌**
   - **설명**: 예약 취소 API(0.5초 완료)를 호출한 직후 문진 제출 API를 호출(4초 지연 완료)하면, 예약 취소는 성공하지만 늦게 완료된 문진 제출 요청이 취소된 예약을 다시 CONFIRMED 상태로 복원시킵니다. 예약 목록에서는 취소됨, 문진 내역에서는 예약 연결 완료로 표시됩니다.

3. **Frontend 정렬 인덱스 오류**
   - **설명**: 문진 내역을 위험도순/통증점수순으로 정렬한 뒤 상세 버튼을 누르면 상단 환자명은 클릭한 환자명으로 뜨지만, 상세 답변과 위험도는 원본 정렬 전 배열의 다른 문진 데이터가 표시됩니다.

4. **통계 집계 불일치**
   - **설명**: 문진 응답을 삭제(`DELETE /api/surveys/:id`) 처리하여 문진 목록에서 소거하더라도, 대시보드 위험도 평균(`surveyStats.averagePainScore`), 진료과별 문진 수, 관리자 검토 대기 건수 수치에는 차감되지 않고 계속 잔존합니다.

5. **Network stale response 오류**
   - **설명**: 진료과 필터('소화기내과' 3초 지연 ➔ '정형외과' 0.2초 완료)와 위험도 필터를 빠르게 변경 시 오래된 응답(소화기내과)이 최신 문진 목록을 덮어써 문진 목록은 오래된 필터 결과, 오른쪽 위험도 요약은 최신 필터 기준 수치로 서로 불일치합니다.

6. **Session + Cache 잔존 오류**
   - **설명**: 환자 A가 문진 내역을 본 뒤 환자 B로 로그인하면 문진 목록은 B 기준으로 바뀌지만, 상단 진행 중 문진 및 최근 예약 요약 캐시(`cachedIncompleteSurvey`, `cachedRecentAppointment`)는 A 데이터가 남아 노출됩니다.

7. **Backend 권한 로그 오류**
   - **설명**: 권한 없는 일반 직원(role !== 'ADMIN')이 문진 위험도 수정 API(`PATCH /api/surveys/:id/risk`)를 호출하면 HTTP 403을 반환하지만, 서버 내부 활동 로그에는 '위험도 수정 성공 (SURVEY RISK LEVEL UPDATED SUCCESSFULLY - 200 OK)'으로 잘못 기록됩니다.

8. **부분 저장 오류**
   - **설명**: 환자 기본정보 수정 모달/패널에서 키, 몸무게, 복용약을 동시에 수정하면 백엔드 data.json에는 키와 복용약만 저장되고 몸무게는 이전 값을 유지하지만, 프론트엔드는 세 항목 모두 수정 성공한 것으로 표시합니다.

## 🧪 테스트 시나리오

1. **Error 1 테스트**: 우측 관제 패널에서 문진 증상 수정 입력 후 `답변 수정 후 즉시 예약 시간 변경 (Error 1)` 클릭 ➔ 0.1초 후 예약 시간 변경 응답 ➔ 3초 후 답변 수정 응답 완료 ➔ 새로고침 시 이전 예약 시간으로 롤백 저장됨을 확인.
2. **Error 2 테스트**: 우측 관제 패널에서 `⚡ 예약 취소 후 문진 제출 연쇄 호출 (Error 2)` 클릭 ➔ 0.5초 후 예약 취소 응답 ➔ 4초 후 문진 제출 응답 완료 ➔ 취소된 예약이 CONFIRMED 상태로 복원됨을 확인.
3. **Error 3 테스트**: 좌측 사이드바에서 `위험도 높은순` 정렬 선택 ➔ 최상단 문진의 `상세` 클릭 ➔ UI 상단 환자명과 우측 관제 패널의 문진 답변/위험도 정보가 상이함을 확인.
4. **Error 4 테스트**: 중앙 문진 대장에서 `🗑️ 문진 응답 삭제` 클릭 ➔ 대장에서는 삭제되나 위험도 평균 및 검토 대기 수치가 유지됨을 확인.
5. **Error 5 테스트**: 좌측 진료과 필터를 `소화기내과` 선택 직후 `정형외과` 선택 ➔ 3초 후 늦은 이전 소화기내과 결과가 최신 정형외과 문진 목록을 덮어씀을 확인.
6. **Error 6 테스트**: 상단 로그인 관계자를 `김문진 과장`에서 `이진료 전문의`로 전환 ➔ 문진 목록은 B로 바뀌나 상단 KPI 진행 중 문진 건수는 A 데이터로 잔존함을 확인.
7. **Error 7 테스트**: 상단 계정을 일반 사원으로 테스트 시 `🔒 일반 직원의 문진 위험도 수정 시도` 클릭 ➔ UI/API는 HTTP 403 오류 반환 ➔ 백엔드 콘솔 로그에는 SUCCESS (200 OK)로 잘못 작성됨을 확인.
8. **Error 8 테스트**: 우측 하단 환자 정보 수정 패널에서 몸무게 포함 입력 후 `환자 정보 저장` 클릭 ➔ 토스트는 성공으로 표시되나 새로고침 시 몸무게만 수정되지 않았음을 확인.
