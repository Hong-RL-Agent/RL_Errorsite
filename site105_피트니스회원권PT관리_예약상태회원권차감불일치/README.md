## 📋 정상 기능 요약

- **피트니스 전사 회원 & 회원권 대장**: 40명 회원 명단, 잔여 횟수, 회원권 만료일 및 35개 보유 회원권 관제.
- **PT 예약 캘린더 & 트레이너 일정**: 45건의 PT 세션 예약(예약완료, 출석, 노쇼, 취소, 만료) 및 12명 트레이너 일정 관제.
- **출석 체크 & 이용권 차감 로그**: 70건의 회원 센터 입장 출석 및 PT 이용권 1회 차감 이력 관리.
- **활동 로그 & 권한 관제**: 80건의 예약/출석/차감 감사 로그 및 수석 트레이너(MANAGER)/스태프(STAFF) 권한 관리.

## ⚠️ 의도적으로 삽입된 8가지 복합 오류 목록

1. **Frontend + Backend 요청 순서 충돌**
   - **설명**: PT 예약 시간을 변경(3초 지연 완료)한 직후 트레이너를 변경(0.1초 완료)하면, 트레이너 변경 API는 먼저 완료되나 3초 뒤 완료되는 시간 변경 API가 요청 시작 시점의 구 DB 스냅샷(이전 트레이너)을 덮어써 저장하여 새로고침 시 예약 캘린더의 트레이너와 회원 상세의 트레이너가 서로 달라집니다.

2. **Backend + JSON DB 상태 충돌**
   - **설명**: 예약 취소 API(0.5초 완료)를 호출한 직후 출석 체크 API를 호출(4초 지연 완료)하면, 예약 취소는 성공하지만 늦게 완료된 출석 체크 요청이 취소된 예약을 다시 ATTENDED 출석 상태로 복원하고 회원권을 차감시킵니다. 예약 목록에서는 취소됨, 회원권 내역에서는 출석으로 차감된 것처럼 표시됩니다.

3. **Frontend 정렬 인덱스 오류**
   - **설명**: 회원 목록을 잔여횟수순/최근방문일순으로 정렬한 뒤 예약 버튼을 누르면 UI 알림은 클릭한 회원명으로 뜨지만, 백엔드 저장 데이터는 정렬 전 원본 배열의 다른 회원 ID에 연결되는 결함입니다.

4. **통계 집계 불일치**
   - **설명**: 출석 로그를 삭제(`DELETE /api/attendance-logs/:id`) 처리하여 출석 목록에서 소거하더라도, 회원별 출석률(`fitnessStats.avgAttendanceRate`), 트레이너별 수업 수, 월별 매출 통계 수치에는 차감되지 않고 계속 잔존합니다.

5. **Network stale response 오류**
   - **설명**: 트레이너 필터('김피트 수석' 3초 지연 ➔ '이웨이트 선임' 0.2초 완료)와 예약 상태 필터를 빠르게 변경 시 오래된 응답(김피트)이 최신 예약 목록을 덮어써 예약 목록은 오래된 필터 결과, 오른쪽 회원권 요약은 최신 필터 기준 수치로 서로 불일치합니다.

6. **Session + Cache 잔존 오류**
   - **설명**: 직원 A가 회원 상세를 본 뒤 직원 B로 로그인하면 회원 목록은 B 권한 기준으로 바뀌지만, 상단 오늘 예약 수 및 최근 회원 상세 캐시(`cachedTodayReservations`, `cachedRecentMember`)는 A 데이터가 남아 노출됩니다.

7. **Backend 권한 로그 오류**
   - **설명**: 권한 없는 스태프 트레이너(role !== 'MANAGER')가 회원권 차감 API(`POST /api/passes/:id/deduct-unauthorized`)를 호출하면 HTTP 403을 반환하지만, 서버 내부 활동 로그에는 '회원권 차감 성공 (MEMBERSHIP PASS DEDUCTED SUCCESSFULLY - 200 OK)'으로 잘못 기록됩니다.

8. **부분 저장 오류**
   - **설명**: 회원 정보 수정 모달/패널에서 연락처, 회원권 만료일, 담당 트레이너를 동시에 수정하면 백엔드 data.json에는 연락처와 담당 트레이너만 저장되고 만료일은 이전 값을 유지하지만, 프론트엔드는 세 항목 모두 수정 성공한 것으로 표시합니다.

## 🧪 테스트 시나리오

1. **Error 1 테스트**: 우측 관제 패널에서 예약 시간 변경 선택 후 `예약 시간 변경 후 즉시 트레이너 변경 (Error 1)` 클릭 ➔ 0.1초 후 트레이너 변경 응답 ➔ 3초 후 시간 변경 응답 완료 ➔ 새로고침 시 이전 트레이너로 롤백 저장됨을 확인.
2. **Error 2 테스트**: 우측 관제 패널에서 `⚡ 예약 취소 처리 후 출석 체크 연쇄 실행 (Error 2)` 클릭 ➔ 0.5초 후 예약 취소 응답 ➔ 4초 후 출석 체크 응답 완료 ➔ 취소된 예약이 ATTENDED 출석 상태로 복원되고 이용권이 차감됨을 확인.
3. **Error 3 테스트**: 좌측 사이드바에서 `잔여 횟수 적은순` 정렬 선택 ➔ 최상단 회원의 `예약` 클릭 ➔ UI 상단 회원명과 우측 관제 패널의 예약 정보가 상이함을 확인.
4. **Error 4 테스트**: 중앙 출석 차감 로그 대장에서 `🗑️ 출석 로그 삭제` 클릭 ➔ 대장에서는 삭제되나 대시보드 출석률 수치가 유지됨을 확인.
5. **Error 5 테스트**: 좌측 트레이너 필터를 `김피트 수석` 선택 직후 `이웨이트 선임` 선택 ➔ 3초 후 늦은 이전 김피트 결과가 최신 이웨이트 예약 목록을 덮어씀을 확인.
6. **Error 6 테스트**: 상단 로그인 트레이너를 `김피트 수석`에서 `이웨이트 선임`으로 전환 ➔ 회원 목록은 B로 바뀌나 상단 KPI 오늘 예약 건수는 A 데이터로 잔존함을 확인.
7. **Error 7 테스트**: 상단 계정을 일반 스태프 트레이너로 테스트 시 `🔒 권한 없는 일반 트레이너의 회원권 임의 차감 시도` 클릭 ➔ UI/API는 HTTP 403 오류 반환 ➔ 백엔드 콘솔 로그에는 SUCCESS (200 OK)로 잘못 작성됨을 확인.
8. **Error 8 테스트**: 우측 하단 회원 정보 수정 패널에서 만료일 포함 입력 후 `회원 정보 저장` 클릭 ➔ 토스트는 성공으로 표시되나 새로고침 시 만료일만 수정되지 않았음을 확인.
